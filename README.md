# FocusFlow — материалы лабораторной работы № 4

Набор документов для продолжения SRS лабораторной работы № 3.

## Состав
- `docs/SDD.md` — описание проектирования системы (Software Design Description).
- `docs/requirements.md` — системные функциональные и нефункциональные требования, приоритеты и трассировка.
- `docs/ADR/ADR-001-modular-monolith.md` — архитектурный стиль.
- `docs/ADR/ADR-002-relational-database.md` — хранение данных.
- `docs/ADR/ADR-003-auth-access-control.md` — аутентификация и разграничение доступа.
- `docs/ADR/ADR-004-rest-api.md` — взаимодействие через REST API.
- `docs/ADR/ADR-005-csv-export.md` — экспорт данных в CSV.
- `docs/planning/iteration-plans.md` — исходный, изменённый и итоговый планы P0/P1/P2.
- `docs/planning/customer-discussion.md` — два учебных раунда обсуждения с заказчиком.
- `docs/traceability.md` — связь системных требований с компонентами и проверками.

## Перед отправкой в репозиторий
1. Сверьте обозначения исходных FR/NFR с SRS из ЛР3 и при необходимости замените их.
2. Проверьте, совпадают ли выбранные технологии с архитектурными решениями предыдущей лабораторной.
3. Если преподаватель требует точное оформление по шаблонам `Templates/sdd/sdd-template.md` и `Templates/adr/adr-template.md`, перенесите содержание в эти шаблоны, сохранив их обязательные разделы.
4. `customer-discussion.md` содержит учебную модель переписки, а не доказательство реальной переписки. Используйте её как сценарий/черновик и замените реальными сообщениями, если это требуется преподавателем.

## Условные оценки
В документах используются значения из подготовленного отчёта: P0 — 55 middle-дней / 11 недель / 17 600 BYN; P1 — 40 middle-дней / 8 недель / 12 800 BYN; P2 — 40 middle-дней + 12 junior-дней / 8 недель / 14 720 BYN.
