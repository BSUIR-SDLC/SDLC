# Калькулятор громкости жизни (вариант 30)

Лабораторная работа №1 — «Жизненный цикл разработки программного обеспечения».
Java (Swing), MVC с **активной моделью**.

## Как собрать и запустить

Из корня проекта:

```bash
javac -d out src/noisecalc/*.java
java -cp out noisecalc.Main
```

Откроется главное окно с кнопкой «Ввести данные».

## Структура проекта (и как объяснять её на защите)

```
src/noisecalc/
├── NoiseModel.java           – Модель (Model), АКТИВНАЯ
├── ModelListener.java        – интерфейс подписчика модели
├── NoiseController.java      – Контроллер (Controller)
├── MainFrame.java            – главная форма (View)
├── InputDialog.java          – доп. окно ввода данных (View)
├── InvalidInputException.java– исключение для некорректного ввода
└── Main.java                 – точка входа, "сборка" MVC
```

### Как работает MVC здесь

1. **View → Controller.** Пользователь нажимает «Ввести данные» → открывается
   `InputDialog`. При нажатии «Рассчитать» диалог вызывает
   `controller.handleInput(...)`, передавая три СТРОКИ из текстовых полей.
2. **Controller → Model.** `NoiseController` парсит строки в `int` и,
   если формат верный, вызывает `model.setData(talk, music, swear)`.
   Если формат неверный (пусто / не число) — контроллер сам бросает
   `InvalidInputException` ещё до модели.
3. **Model проверяет диапазон и считает результат.** Метод
   `NoiseModel.setData()` проверяет, что каждое число в диапазоне
   [0; 200] (иначе — `InvalidInputException`), затем пересчитывает
   баллы и рекомендацию.
4. **Model → View (это и есть "активность" модели).** После успешного
   пересчёта модель сама вызывает `notifyListeners()`, который проходит
   по списку подписчиков (`List<ModelListener>`) и вызывает у каждого
   `onModelChanged(this)`. `MainFrame` реализует `ModelListener` и
   подписывается на модель в конструкторе (`model.addListener(this)`),
   поэтому она узнаёт об изменении данных не потому, что сама их
   запросила, а потому, что модель её **уведомила**. Это ключевое
   отличие активной модели от пассивной (в пассивной модели
   контроллер или представление сами читали бы геттеры модели после
   вызова setData — здесь View вообще не знает, когда именно
   произошёл вызов setData, оно просто реагирует на push-уведомление).
5. **Ошибки** (из контроллера или модели) ловятся в `InputDialog` и
   показываются через `JOptionPane.showMessageDialog(...)` — окно не
   закрывается, пока данные не станут корректными.
6. **Запоминание последних данных.** `NoiseModel` хранит последние
   *успешно принятые* значения `talkCount/musicCount/swearCount`.
   При повторном открытии `InputDialog` эти значения подставляются в
   текстовые поля (`restoreValue(...)`).

### Формула и пороги (придуманы для лабораторной)

```
score = разговоры * 1.0 + музыка * 1.5 + ругань * 2.5
```

Весовые коэффициенты отражают "шумность" каждого источника:
обычный разговор — базовый уровень (1.0), музыка обычно громче и
длится дольше (1.5), а ругань — самый раздражающий и "громкий" по
эмоциональному воздействию фактор (2.5).

| Баллы (score) | Категория | Рекомендация |
|---|---|---|
| 0 – 20   | Низкий  | Всё спокойно — доп. меры не нужны |
| 20 – 50  | Средний | Караоке — можно выпустить пар |
| > 50     | Высокий | Беруши — шума многовато |

Допустимый диапазон каждого введённого числа: **0–200** раз в день
(отрицательные и нереалистично большие значения отклоняются с понятной
ошибкой).

## Ответы на контрольные вопросы (кратко)

1. **Компоненты IDE:** редактор кода (с подсветкой синтаксиса и
   автодополнением), компилятор/интерпретатор, отладчик, система
   сборки, менеджер проекта/файлов, интеграция с VCS.
2. **Работа с редактором:** автодополнение (Ctrl+Space), быстрая
   навигация (Ctrl+клик по методу/классу), рефакторинг (переименование,
   извлечение метода), форматирование кода, поиск использований.
3. **Сборка и запуск:** в IntelliJ IDEA — кнопка Run (Shift+F10),
   IDE сама вызывает `javac` для компиляции в `.class`-файлы и `java`
   для запуска класса с `main`; вручную — `javac` + `java` из терминала,
   как показано выше.
4. **MVC** — паттерн, разделяющий приложение на Модель (данные и
   бизнес-логика), Представление (интерфейс, показывает данные) и
   Контроллер (обрабатывает ввод пользователя и обновляет модель).
5. **Активная vs пассивная модель:** активная модель сама оповещает
   подписчиков об изменении состояния (как в этом проекте — через
   `ModelListener`); пассивная модель ничего не знает о представлении —
   после изменения данных именно контроллер (или представление)
   должен сам явно запросить у модели новые данные и обновить экран.
