# Напоминания в Telegram через Bot API с длинным опросом и стратегию каналов

## Контекст и постановка задачи

Во втором раунде обсуждения Заказчик вернул напоминания в Telegram в релиз 1.0 (письмо 5): письма попадают в спам, а Telegram пользователи читают. Пользователь должен привязать Telegram к учётной записи и выбрать канал напоминаний (REQ-FUNC-011-3, REQ-FUNC-023, REQ-INT-004). Ограничение CON-9 уточнено: текст напоминания передаётся Telegram только если пользователь сам привязал Telegram (CON-9-2). На всё отведено 17 ч (план v3).

Как получать от Telegram команду привязки и отправлять сообщения, не усложняя развёртывание, и как встроить второй канал в существующие напоминания?

## Драйверы решения

* трудоёмкость не более 17 ч и срок 25.12.2026;
* сервер без дополнительных входящих адресов и сертификатов (011-deployment);
* бесплатность и отсутствие посредников (REQ-COST-001, CON-9-2);
* единая логика напоминаний для обоих каналов (без дублирования ReminderJob).

## Рассмотренные варианты

* Telegram Bot API, получение обновлений длинным опросом `getUpdates`
* Telegram Bot API, получение обновлений через webhook
* Сторонний сервис рассылок с интеграцией Telegram

## Итог решения

Выбранный вариант: «Bot API с длинным опросом», потому что он не требует входящих соединений к приложению и отдельного публичного адреса, одинаково работает на ноутбуке разработчика и на сервере и при нагрузке до 100 пользователей не уступает webhook. Отправка встроена как реализация `TelegramChannel` интерфейса `NotificationChannel` (шаблон «Стратегия»), поэтому `ReminderJob`, `RetryJob` и журнал уведомлений (ADR-0005) используются без изменений.

### Последствия

* Хорошо, потому что разработка и тестирование не зависят от публичного адреса: заглушка Bot API подменяет `TelegramClient`.
* Хорошо, потому что новый канал (например, push после 1.0) добавляется ещё одной реализацией `NotificationChannel`.
* Плохо, потому что приложение держит постоянный длинный запрос к api.telegram.org (один поток).
* Нейтрально, потому что при блокировке бота пользователем (ответ 403) канал автоматически переключается на e-mail, а пользователь видит это в настройках.

### Подтверждение

Тесты с заглушкой Bot API: команда `/start` с действующим кодом сохраняет `chat_id`; с просроченным — отвечает «код недействителен»; ответ 403 переключает канал на EMAIL. Демонстрация Заказчику на показе итерации 5.

## Плюсы и минусы вариантов

### Bot API, длинный опрос

* Хорошо, потому что нет входящих соединений и настройки nginx.
* Хорошо, потому что работает за NAT на ноутбуке разработчика.
* Плохо, потому что задержка доставки команды — до 25 с (для привязки несущественно).

### Bot API, webhook

* Хорошо, потому что Telegram сам доставляет обновления сразу.
* Плохо, потому что нужен публичный HTTPS-адрес, отдельный маршрут, проверка секрета и отдельная настройка для разработки.

### Сторонний сервис рассылок

* Хорошо, потому что готовый интерфейс управления рассылками.
* Плохо, потому что данные пользователей передаются ещё одной третьей стороне (нарушение CON-9-2) и бесплатные тарифы ограничены (REQ-COST-001).
