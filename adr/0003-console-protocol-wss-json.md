# Протокол консоли: WebSocket поверх TLS 1.3 с сообщениями JSON

## Контекст и постановка задачи

Консоль должна узнавать о новом инциденте не позже 3 секунд после события и отправлять действия оператора. Консолей единицы, но запросы разнообразные. В Unreal Engine 5 есть модуль WebSockets и разбор JSON, но нет удобной работы с «голым» TLS-сокетом. Как консоль обменивается данными с сервером?

Связанные требования: REQ-INT-008, REQ-FUNC-015, REQ-PERF-001, REQ-SEC-001, REQ-SEC-007. Элемент дизайна: DV-005.

## Драйверы решения

* Сервер должен сам сообщать консоли о событиях (REQ-FUNC-015).
* Задержка до 3 секунд (REQ-PERF-001).
* Готовая поддержка в UE5 без сторонних библиотек.
* Простота отладки.

## Рассмотренные варианты

* Тот же двоичный протокол, что у агента
* REST по HTTPS с опросом раз в секунду
* gRPC со стримингом
* WebSocket поверх TLS с JSON

## Итог решения

Выбранный вариант: «WebSocket поверх TLS с JSON», потому что сервер может сам отправлять сообщения консоли, а в UE5 и на сервере (Boost.Beast) есть готовая поддержка.

### Последствия

* Хорошо, потому что новые инциденты появляются в консоли сразу, без опроса.
* Хорошо, потому что сообщения читаются глазами и отлаживаются из браузера.
* Плохо, потому что на сервере два разных протокола и два обработчика.
* Плохо, потому что схему JSON проверяем сами, генератора кода нет.

### Подтверждение

Интеграционный тест: тестовый клиент на Python входит по wss, получает план здания и push-сообщение о новом инциденте. Сообщения больше 64 КБ отклоняются.

## Плюсы и минусы вариантов

### Тот же двоичный протокол, что у агента

* Хорошо, потому что один протокол на всю систему.
* Плохо, потому что в UE5 пришлось бы писать TLS-сокет и разбор кадров вручную.

### REST по HTTPS с опросом

* Хорошо, потому что самый простой вариант.
* Плохо, потому что задержка до секунды и лишняя нагрузка от пустых запросов.

### gRPC со стримингом

* Хорошо, потому что строгая схема и двусторонние потоки.
* Плохо, потому что для UE5 нет простой готовой поддержки.

### WebSocket поверх TLS с JSON

* Хорошо, потому что есть push и готовые библиотеки.
* Нейтрально, потому что объём JSON больше, но для единиц консолей это не важно.

## Дополнительная информация

Перечень запросов и ответов приведён в DV-005.

Сообщения протокола используются на диаграммах последовательности SD-01 (`login`, `login_ok`) и SD-02 (`set_incident_status`, `incident_update`, `host_state`) в DV-018 и DV-019. Асинхронные стрелки на этих диаграммах соответствуют сообщениям WebSocket, а рассылка другим консолям – шаблону Publisher – Subscriber из DV-011.
