# ADR-0004. Шифрование ключа Steam AES-256-GCM, мастер-ключ в хранилище ОС

## Контекст и постановка задачи

Ключ Steam Web API даёт доступ к данным учётной записи пользователя. REQ-SEC-001 требует хранить его зашифрованным, не показывать целиком и не допускать в журналы и резервные копии. Где и как хранить ключ?

## Драйверы решения

* REQ-SEC-001
* Не просить у пользователя дополнительный пароль
* REQ-PORT-001: одинаковое поведение на Windows и Linux

## Рассмотренные варианты

* AES-256-GCM, мастер-ключ в Windows Credential Manager / Secret Service
* Открытый текст в настройках
* Шифрование паролем пользователя

## Итог решения

Выбранный вариант: «AES-256-GCM, мастер-ключ в Windows Credential Manager / Secret Service», потому что это единственный вариант, выполняющий REQ-SEC-001 без лишних действий пользователя.

### Последствия

* Хорошо, потому что ключ исключён из базы, журналов и резервной копии
* Плохо, потому что при отсутствии Secret Service ключ не сохраняется и запрашивается при каждом импорте

### Подтверждение

Проверка `security/secret-scan.md`: поиск строки ключа в файле БД, журналах и резервных копиях не находит совпадений.

## Плюсы и минусы вариантов

### AES-256-GCM, мастер-ключ в Windows Credential Manager / Secret Service

Ключ шифруется, ключ шифрования хранит ОС.

* Хорошо, потому что ключ не лежит рядом с базой в открытом виде
* Хорошо, потому что пароль не нужен
* Плохо, потому что нужен запасной режим для Linux без Secret Service

### Открытый текст в настройках

Ключ хранится как обычная настройка.

* Хорошо, потому что просто
* Плохо, потому что нарушает REQ-SEC-001

### Шифрование паролем пользователя

Ключ расшифровывается введённым паролем.

* Хорошо, потому что не зависит от ОС
* Плохо, потому что пароль приходится вводить при каждом импорте и его забывают

## Дополнительная информация
