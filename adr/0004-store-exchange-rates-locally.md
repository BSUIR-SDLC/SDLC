# Курсы НБ РБ хранятся в собственной таблице с ежедневной загрузкой

## Контекст и постановка задачи

Все суммы в SubScope пересчитываются в базовую валюту по официальному курсу НБ РБ (REQ-INT-002-2, REQ-FUNC-013). Страница «Обзор» может содержать десятки пересчётов, аналитика — курсы за 12 месяцев (REQ-FUNC-014-2). API НБ РБ бесплатен и доступен без ключа, но может быть недоступен (ASM-1).

Откуда брать курс при каждом пересчёте, чтобы страницы формировались за 2 с (REQ-PERF-001) и работали при недоступности API (REQ-REL-001)?

## Драйверы решения

* время ответа страницы не более 2 с (REQ-PERF-001);
* работа по последним курсам без API (REQ-REL-001);
* исторические курсы для аналитики и прошедших списаний (REQ-FUNC-013, 014-2);
* не чаще одного запроса текущих курсов в сутки (REQ-INT-002-2).

## Рассмотренные варианты

* Запрос к API при каждом пересчёте
* Кэш курсов в памяти приложения
* Таблица `exchange_rate` с ежедневной загрузкой

## Итог решения

Выбранный вариант: «Таблица `exchange_rate` с ежедневной загрузкой», потому что это единственный вариант, который выполняет все четыре драйвера и сохраняет курсы после перезапуска сервера.

### Последствия

* Хорошо, потому что пересчёт — запрос к локальной таблице по первичному ключу.
* Хорошо, потому что накопленная история курсов используется аналитикой без дополнительных запросов.
* Плохо, потому что нужна задача загрузки, повторы и обработка отсутствия курса — это и объясняет оценку 22 ч (письмо 3).
* Нейтрально, потому что курс на сегодня появляется после 00:10; до первой загрузки используется вчерашний курс с указанием его даты.

### Подтверждение

Интеграционный тест с заглушкой `NbrbClient`: при ошибке API пересчёт выполняется по последнему курсу, на странице выводится его дата. Проверка концепции REQ-POC-001 — задача T-03.1 итерации 1.

## Плюсы и минусы вариантов

### Запрос к API при каждом пересчёте

* Хорошо, потому что всегда свежий курс без хранения.
* Плохо, потому что десятки сетевых запросов на страницу нарушают REQ-PERF-001 и REQ-INT-002-2.
* Плохо, потому что при недоступности API страницы перестают работать (REQ-REL-001).

### Кэш курсов в памяти

* Хорошо, потому что быстро.
* Плохо, потому что после перезапуска сервера кэш пуст, и при недоступности API курсов нет.
* Плохо, потому что исторические курсы пришлось бы запрашивать заново.

### Таблица `exchange_rate`

* Хорошо, потому что быстро, надёжно и с историей.
* Плохо, потому что нужна фоновая задача и её мониторинг через журнал.

## Дополнительная информация

SDD: 006-interaction (рисунок 3.11), 007-algorithm (А1, А4), 009-concurrency, 012-resources. Версия плана v2: влияние курса считается по курсам на первое число месяца, чтобы ограничиться 12 запросами на валюту.

UML-модель (ЛР5, ADR-0008): решение реализует прецедент UC-20 «Загрузить курсы валют» и включаемый UC-24 «Пересчитать в базовую валюту» ([uml/use-cases.md](../uml/use-cases.md)). Диаграмма последовательности [sq-4-rates](../uml/models/sq-4-rates.mmd) показывает механизм: проверка наличия курса на сегодня в таблице, цикл до трёх попыток и работа по последнему сохранённому курсу; таблица `exchange_rate` — единственный источник курсов для всех прецедентов, включающих UC-24 (рисунок 3.3 SDD).
