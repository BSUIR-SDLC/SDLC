# Серверные шаблоны с лёгким JavaScript для схемы зала

## Контекст и постановка задачи

Нужен web-интерфейс для покупателя, администратора и контролёра (REQ-INT-001…006) с интерактивной схемой зала и таймером брони. Какой подход к интерфейсу выбрать при ограничениях по срокам и бюджету?

## Драйверы решения

* Интерактивность только в схеме зала и таймере
* Срок и размер команды (один разработчик)
* Работа на экранах от 320 px и доступность WCAG 2.1 AA (REQ-COMP-001)
* Простота сборки и развёртывания (REQ-INST-001)

## Рассмотренные варианты

* Серверные шаблоны (Jinja2) и небольшой JS для схемы зала
* SPA на React
* Только серверные шаблоны без JS

## Итог решения

Выбранный вариант: «Серверные шаблоны (Jinja2) и небольшой JS для схемы зала», потому что он закрывает все экраны без отдельной frontend-сборки, а интерактивность ограничена одним компонентом.

### Последствия

* Хорошо, потому что один деплой и нет отдельного frontend-проекта
* Хорошо, потому что страницы работают быстро и их проще сделать доступными
* Плохо, потому что сложный интерактив придётся писать вручную
* Плохо, потому что при росте интерфейса может потребоваться переход на SPA

### Подтверждение

Ручная проверка экранов на ширине 320 px; автоматическая проверка доступности (например, axe) в CI; ревью размера клиентского JS.

## Плюсы и минусы вариантов

### Серверные шаблоны (Jinja2) и небольшой JS для схемы зала

* Хорошо, потому что быстро и просто развернуть
* Хорошо, потому что JS ограничен одним компонентом
* Плохо, потому что интерактив в схеме зала пишется вручную

### SPA на React

* Хорошо, потому что богатый интерактив и готовые компоненты
* Плохо, потому что отдельный проект, сборка и больше времени

### Только серверные шаблоны без JS

* Хорошо, потому что самое простое решение
* Плохо, потому что нет таймера и удобного выбора мест, что противоречит REQ-FUNC-003 и REQ-FUNC-005

## Дополнительная информация

Затрагивает REQ-INT-001…006, REQ-COMP-001, REQ-INST-001; представления DV-002, DV-011. Решение пересматривается, если потребуется мобильное приложение или значительно более сложный интерфейс.
