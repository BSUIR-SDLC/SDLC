# Модульный монолит для TicketFlow

## Контекст и постановка задачи

Один экземпляр Java 17 и одна БД соответствуют границам стенда; как разделить ответственность без распределённых транзакций? Требования: REQ-BUILD-001, REQ-DIST-001, REQ-REL-002. Представления SDD: 002, 005, 006, 013, 014.

## Драйверы решения

* Атомарность покупки
* Ограниченный срок и бюджет
* Сопровождаемость

## Рассмотренные варианты

* Модульный монолит
* Микросервисы

## Итог решения

Выбранный вариант: «Модульный монолит», потому что единая транзакция сохраняет продажу и билеты, а модули локализуют изменения. Решение предложено для рассмотрения; статус указан в метаданных.

### Последствия

* Хорошо, потому что один выпуск и один процесс упрощают стенд.
* Плохо, потому что модули выпускаются вместе, возможна связанность при нарушении границ.
* Нейтрально: требования остаются проверяемыми по SRS, но сами проверки ещё не выполнены.

### Подтверждение

Инспекция зависимостей пакетов; покупка и восстановление проверяются интеграционно. Результат проверки будет записан после реализации; сейчас статус Planned.

## Плюсы и минусы вариантов

### Модульный монолит

* Хорошо, потому что один выпуск и один процесс упрощают стенд.
* Хорошо, потому что единая транзакция сохраняет продажу и билеты, а модули локализуют изменения.
* Нейтрально: применяется в пределах тестового стенда, промышленный масштаб не обещается.
* Плохо, потому что модули выпускаются вместе, возможна связанность при нарушении границ.

### Микросервисы

* Хорошо: Компоненты можно выпускать независимо.
* Хорошо: Границы сервисов могут соответствовать разным командам.
* Нейтрально: бизнес-критерии SRS сохраняются; альтернатива требует собственного подтверждения их выполнения.
* Плохо: Распределённые транзакции, развёртывание и наблюдаемость увеличивают объём относительно 240 ч.

## Дополнительная информация

[SDD](../sdd/sdd.md), [SRS](../srs/srs.md). Решение пересматривается при изменении границ релиза, нагрузки, состава команды либо при провале указанных проверок. Статус accepted устанавливается после согласования решения.
