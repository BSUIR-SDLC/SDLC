# PostgreSQL с отдельными пользователями для приложения и аудита, партиции событий по дням

## Контекст и постановка задачи

Система хранит события 90 дней, инциденты и журнал действий операторов. Если сервер работает с базой под владельцем схемы, любая ошибка или SQL-инъекция даёт полный доступ, включая подделку журнала аудита. Таблица событий растёт быстрее всех, и старые данные нужно удалять, не давая серверу прав на изменение схемы. Какую СУБД использовать и как разграничить права?

Связанные требования: REQ-INT-009, REQ-SEC-005, REQ-SEC-010, REQ-PERF-005, REQ-COMP-001. Элемент дизайна: DV-003.

## Драйверы решения

* Отсутствие платных лицензий (REQ-COMP-001).
* Журнал действий только дописывается (REQ-SEC-005).
* Минимальные права приложения (REQ-SEC-010).
* Хранение событий 90 дней (REQ-PERF-005).

## Рассмотренные варианты

* PostgreSQL, один пользователь с полными правами
* PostgreSQL, пользователи smc_app и smc_audit, партиции по дням
* Microsoft SQL Server

## Итог решения

Выбранный вариант: «PostgreSQL, пользователи smc_app и smc_audit, партиции по дням», потому что он бесплатен, поддерживает секционирование таблиц и позволяет лишить приложение доступа к журналу аудита. Партиции создают и удаляют функции с правами владельца, сервер только вызывает их.

### Последствия

* Хорошо, потому что взломанный сервер не может изменить схему и журнал аудита.
* Хорошо, потому что удаление старых данных – это удаление целой партиции, а не долгий DELETE.
* Плохо, потому что серверу нужны два пула соединений и два пароля.

### Подтверждение

Проверочные запросы под smc_app: UPDATE ролей, DELETE событий и SELECT из audit_log должны завершаться ошибкой «permission denied».

## Плюсы и минусы вариантов

### PostgreSQL, один пользователь с полными правами

* Хорошо, потому что ничего не надо настраивать.
* Плохо, потому что взломанный сервер может подделать журнал.

### PostgreSQL, пользователи smc_app и smc_audit, партиции по дням

* Хорошо, потому что минимальные права и быстрая очистка.
* Нейтрально, потому что настройка прав описывается в миграции один раз.

### Microsoft SQL Server

* Хорошо, потому что развитые средства администрирования.
* Плохо, потому что платная лицензия для промышленного использования.

## Дополнительная информация

Решение связано с ADR-0005: проверка паролей выполняется сервером, а не СУБД.
