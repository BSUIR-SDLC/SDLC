# Backend на Python с фреймворком FastAPI

## Контекст и постановка задачи

Для системы «EasyTicket» нужен backend с REST API (SRS 3.1.3), генерацией QR-кодов библиотекой qrcode (REQ-FUNC-007), отправкой писем и OpenAPI-описанием (REQ-MAINT-002). Какой язык и фреймворк выбрать, чтобы уложиться в сроки при команде из одного разработчика?

## Драйверы решения

* Библиотека qrcode обязательна (SRS 2.3), поэтому нужен язык с её поддержкой (Python)
* Автоматическая документация API (REQ-MAINT-002)
* Срок реализации и малый размер команды
* Возможность фоновых задач (REQ-PERF-004, REQ-REL-001)
* Покрытие тестами не менее 70 % (REQ-MAINT-001)

## Рассмотренные варианты

* FastAPI
* Django REST Framework
* Flask

## Итог решения

Выбранный вариант: «FastAPI», потому что он автоматически формирует OpenAPI/Swagger, поддерживает асинхронные обработчики и фоновые задачи, требует меньше шаблонного кода, чем Django, и хорошо подходит для небольшого REST-сервиса.

### Последствия

* Хорошо, потому что документация API создаётся из кода и не расходится с реализацией
* Хорошо, потому что валидация входных данных (email, лимит мест) описывается типами
* Плохо, потому что встроенной админ-панели нет, её придётся писать самостоятельно (REQ-FUNC-012…014)
* Плохо, потому что команде нужно освоить асинхронную модель

### Подтверждение

Ревью структуры проекта; наличие страницы `/docs` (Swagger UI) в CI-проверке; тесты API на покрытие не менее 70 %.

## Плюсы и минусы вариантов

### FastAPI

* Хорошо, потому что OpenAPI формируется автоматически
* Хорошо, потому что быстрая разработка небольшого API
* Нейтрально, потому что экосистема моложе, чем у Django
* Плохо, потому что нет готовой админ-панели

### Django REST Framework

* Хорошо, потому что есть встроенная админ-панель и ORM
* Нейтрально, потому что OpenAPI подключается отдельным пакетом
* Плохо, потому что больше шаблонного кода и объём изучения для небольшой системы

### Flask

* Хорошо, потому что минимальный размер и простота
* Плохо, потому что валидацию, документацию и фоновые задачи нужно собирать из отдельных библиотек
