# ADR-002. Моделирование динамического поведения на UML в текстовом виде

- Статус: принято
- Дата: 2026-11-22
- Автор: Овсяник А.Н.

## Контекст и проблема
В ЛР5 требуется построить use-case, активность, состояния и последовательность. Диаграммы должны храниться в репозитории рядом с кодом, сравниваться в pull-request и не зависеть от платного редактора.

## Драйверы решения
- diff-friendly формат, отображение на GitHub;
- воспроизводимость построения (команда в терминале);
- согласованность диаграмм между собой и с требованиями.

## Рассмотренные варианты
| Вариант | Плюсы | Минусы | Итог |
|---------|-------|--------|------|
| 1. Mermaid + PlantUML (текст) | версионируется, рецензируется построчно, Mermaid рендерится GitHub | нет ручной раскладки | **Принято** |
| 2. Только PlantUML | единый язык | нужен Java/сервер для рендера, нет предпросмотра на GitHub | Отклонено |
| 3. Графический редактор (draw.io, Visio) | гибкая раскладка | бинарные файлы, нет осмысленного diff | Отклонено |

## Решение
Использовать Mermaid для диаграмм активности, состояний и последовательности и PlantUML для use-case (`uml/src/`). PNG генерируются из исходников и хранятся рядом (`uml/`).

## Механизм построения и связи диаграмм
1. Прецедент (`docs/use-cases.md`) фиксирует цель, пред- и постусловия и потоки событий.
2. Диаграмма активности повторяет основной и альтернативные потоки UC-02, 03, 05…08: каждый ромб решения — условие потока (фильтры корректны, мест достаточно, бронь действует).
3. Диаграммы состояний выделяют объекты, чьё состояние меняется в активности: бронь/корзина (Empty → Active → Expired/Ordered) и билет (Valid → Refunded). События переходов совпадают с действиями активности (AddToCart, Timeout, Checkout).
4. Диаграммы последовательности показывают, какие модули обмениваются сообщениями: UI-компоненты, `cart.ts`, `catalog.ts`, REST API; коды ответов 409/410 соответствуют ошибочным потокам прецедентов.
5. Каждая диаграмма ссылается на REQ-/FEAT- в таблице `docs/uml.md`.

Связи в use-case: `include` — обязательное поведение (вход для заказа и билетов, резервирование при добавлении в корзину); `extend` — необязательное (фильтры, промокод, PDF); связи между актёрами не моделируются.

## Последствия
- (+) диаграммы меняются вместе с кодом и проверяются в PR;
- (+) единый словарь терминов из `docs/glossary.md`;
- (−) раскладку нельзя править вручную — только через исходник;
- (−) при изменении сценария нужно обновить цепочку «прецедент → активность → состояния → последовательность».
