# Architectural Decision Record (ADR)
## ADR-001: Architecture and Storage Selection for Freelancer Cabinet

### Status
Accepted

### Context
Необходимо обеспечить надежный учет статусов заказов и запретить выплату вознаграждения без загруженного артефакта работы. На текущем этапе разрабатывается прототип в виде CLI-приложения.

### Decision
1. Архитектура: Модульная с четким разделением (UI -> Сервисный слой -> Хранилище).
2. Стек технологий: C++17, стандартная библиотека STL (vector, map, string).
3. Управление состояниями: Использование enum class TaskStatus для строгой фиксации этапов задачи.
4. Валидация сдачи: Запрет перехода в статус оплаты при отсутствии зафиксированного пути к файлу.

### Consequences
* Плюсы: Простота сборки через MinGW, отсутствие внешних тяжелых зависимостей, защита от несанкционированного начисления средств.
* Минусы: Данные хранятся в оперативной памяти (персистентная БД SQLite планируется на следующих этапах).
