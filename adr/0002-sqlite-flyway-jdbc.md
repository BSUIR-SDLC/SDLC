# ADR-0002. SQLite в режиме WAL, миграции Flyway, доступ через JDBC без ORM

## Контекст и постановка задачи

Данные должны храниться локально в одном файле в профиле пользователя (C-2), изменения – выполняться транзакционно (REQ-REL-002), схема – меняться только миграциями (C-5, REQ-CM-001). Объём – до 5000 игр и 50 000 сессий, фильтр библиотеки ≤ 300 мс, статистика ≤ 1 с. Какое хранилище и способ доступа выбрать?

## Драйверы решения

* C-2: один файл в профиле пользователя
* REQ-REL-002: транзакции и восстановление после сбоя
* REQ-PERF-001: запуск ≤ 3 с
* REQ-PERF-002/003: фильтр ≤ 300 мс, статистика ≤ 1 с

## Рассмотренные варианты

* SQLite + JDBC + Flyway
* H2 во встроенном режиме + Hibernate
* Файлы JSON без СУБД

## Итог решения

Выбранный вариант: «SQLite + JDBC + Flyway», потому что он выполняет C-2 и REQ-REL-002 без дополнительных средств и даёт быстрые агрегирующие запросы для статистики.

### Последствия

* Хорошо, потому что резервная копия и перенос данных сводятся к одному файлу
* Хорошо, потому что режим WAL снижает риск повреждения базы при аварийном завершении
* Плохо, потому что запросы статистики нужно покрывать тестами на эталонной базе

### Подтверждение

Тест `ImportAtomicityTest` (обрыв процесса во время импорта не оставляет частичных данных) и бенчмарк REQ-PERF-003 на базе из 50 000 сессий.

## Плюсы и минусы вариантов

### SQLite + JDBC + Flyway

Встраиваемая СУБД в одном файле, запросы на SQL, миграции версиями.

* Хорошо, потому что один файл, транзакции и режим WAL «из коробки»
* Хорошо, потому что агрегаты статистики считаются одним SQL-запросом
* Плохо, потому что SQL пишется вручную

### H2 во встроенном режиме + Hibernate

Java-СУБД и ORM.

* Хорошо, потому что меньше кода доступа к данным
* Плохо, потому что Hibernate заметно замедляет холодный старт (REQ-PERF-001)
* Плохо, потому что поведение файла при аварийном завершении менее предсказуемо

### Файлы JSON без СУБД

Данные сериализуются в файлы.

* Хорошо, потому что нет зависимостей
* Плохо, потому что нет транзакций и запросов, статистика по 50 000 сессий считается в памяти
