# ADR-0003. Автоотслеживание опросом ProcessHandle раз в 5 секунд

## Контекст и постановка задачи

REQ-FUNC-007 требует автоматически начинать и завершать игровую сессию по процессу игры на Windows и Linux с погрешностью границ ≤ 10 с и нагрузкой ≤ 1 % CPU (REQ-PERF-004). Раздел 3.5.9 SRS предписывает проверить осуществимость прототипом. Как обнаруживать запуск и завершение игры?

## Драйверы решения

* REQ-PORT-001: одинаковое поведение на Windows и Ubuntu
* REQ-PERF-004: ≤ 1 % CPU и ≤ 150 МБ ОЗУ в фоне
* Погрешность границ сессии ≤ 10 с
* Один разработчик без опыта нативного кода

## Рассмотренные варианты

* Опрос `ProcessHandle.allProcesses()` каждые 5 с
* Вызов системных утилит (`tasklist`, `ps`)
* Нативные события ОС через JNA (WMI, netlink)

## Итог решения

Выбранный вариант: «Опрос `ProcessHandle.allProcesses()` каждые 5 с», потому что он удовлетворяет REQ-PORT-001 и REQ-PERF-004 одним кроссплатформенным кодом, а погрешность 5 с укладывается в допуск 10 с.

### Последствия

* Хорошо, потому что код `platform` для двух ОС отличается только получением пути к файлу
* Плохо, потому что для игр, запускаемых через лаунчер, нужно уточнить, какой процесс отслеживать (открытый вопрос плана)
* Плохо, потому что решение зависит от результата прототипа (12 ч в итерации 1)

### Подтверждение

Прототип на пяти играх на Windows 11 и Ubuntu 22.04; тест `ProcessWatcherTest`; замер CPU за 1 ч игры (REQ-PERF-004).

## Плюсы и минусы вариантов

### Опрос `ProcessHandle.allProcesses()` каждые 5 с

Стандартный API Java 9+.

* Хорошо, потому что один код для обеих ОС
* Хорошо, потому что погрешность не превышает периода опроса
* Плохо, потому что у части процессов путь к файлу недоступен без прав

### Вызов системных утилит (`tasklist`, `ps`)

Запуск внешней команды и разбор её вывода.

* Хорошо, потому что работает везде
* Плохо, потому что запуск процесса каждые 5 с дороже по CPU
* Плохо, потому что разбор текста хрупок

### Нативные события ОС через JNA (WMI, netlink)

Подписка на события создания процессов.

* Хорошо, потому что реакция мгновенная
* Плохо, потому что нужны две нативные реализации и сложная отладка

## Дополнительная информация

Если путь к файлу недоступен, сравнение выполняется по имени процесса. При неуспехе прототипа запись заменяется новой с вариантом 2. Связано с представлениями 007-interaction и 010-concurrency.
