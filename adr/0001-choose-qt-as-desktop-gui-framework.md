# ADR-001: Выбор графического фреймворка Qt 6 Widgets для десктопного интерфейса

## Контекст и постановка задачи

Проектируемое приложение «HabitFlow C++» предназначено для локального контроля распорядка дня на персональных компьютерах под управлением ОС Windows и Linux. В соответствии с SRS, система должна обеспечивать холодный запуск менее чем за 1.0 с (REQ-PERF-001), отображать интерактивный календарь с кастомной цветовой заливкой ячеек (REQ-FUNC-006 / REQ-SYS-007), а также поддерживать работу в системном трее операционной системы (REQ-SYS-011).

Какую библиотеку/фреймворк следует выбрать для построения графического интерфейса пользователя (GUI) на C++?

## Драйверы решения

* **Кроссплатформенность (REQ-PORT-001):** единая кодовая база без платформозависимых #ifdef для Windows 10/11 и Linux.
* **Производительность и время старта (REQ-PERF-001):** мгновенная инициализация без тяжёлых Web-движков.
* **Развитая компонентная база (REQ-INT-001):** поддержка кастомных календарей (делегаты `QStyledItemDelegate`), чек-боксов, прогресс-баров.
* **Фоновая работа в системном трее (REQ-SYS-011):** нативная поддержка `QSystemTrayIcon` и таймеров `QTimer`.
* **Лицензионная чистота и стоимость (REQ-COST-001):** возможность использования под LGPLv3 без коммерческих выплат.

## Рассмотренные варианты

* **Qt 6 Widgets (C++)** — зрелый промышленный фреймворк с нативным оконным рендерингом.
* **Dear ImGui** — легковесная библиотека немедленного режима (immediate mode GUI).
* **Нативный Win32 API / C++** — низкоуровневая разработка под Windows.
* **Electron / C++ Addon** — веб-интерфейс на HTML/JS с бэкендом на C++.

## Итог решения

Выбран вариант: **«Qt 6 Widgets»**, потому что это единственный вариант, объединяющий полноценную кроссплатформенность, готовую компонентную базу (включая работу с календарями и треем) и гарантированное время запуска до 0.5 с при компиляции в нативный машинный код.

### Последствия

* **Хорошо:** Богатый набор готовых элементов управления исключает необходимость «велосипедостроения» сложных виджетов с нуля.
* **Хорошо:** Высокая скорость рендеринга и нативный внешний вид под целевую ОС (стили QSS).
* **Хорошо:** Наличие проверенных механизмов работы со временем (`QTimer`), звуком (`QSoundEffect`) и треем (`QSystemTrayIcon`).
* **Плохо:** Увеличение размера дистрибутива на 30–50 МБ за счёт динамических библиотек Qt (QtCore, QtGui, QtWidgets).
* **Плохо:** Необходимость использования сборочного инструмента MOC (Meta-Object Compiler) через CMake.

### Подтверждение

Соблюдение подтверждается сборкой прототипа через `CMake` 3.16+ с таргетом `Qt6::Widgets` и автоматическим замером времени холодного старта через утилиту бенчмаркинга (`< 0.6 с`).

## Плюсы и минусы вариантов

### Qt 6 Widgets

* Хорошо, потому что предоставляет мощный механизм делегатов `QStyledItemDelegate` для интерактивного календаря.
* Хорошо, потому что поддерживает сигнально-слотовую архитектуру и слабую связанность слоёв.
* Хорошо, потому что нативно кроссплатформенный (Linux/Windows/macOS).
* Плохо, потому что требует линковки библиотек Qt runtime.

### Dear ImGui

* Хорошо, потому что сверхлегковесный (добавляет менее 2 МБ к бинарнику) и быстрый.
* Нейтрально, потому что ориентирован на разработку игровых движков и отладочных панелей.
* Плохо, потому что отсутствует нативная поддержка стандартных десктопных контролов (системный трей, контекстные меню ОС, доступность для клавиатуры).
* Плохо, потому что постоянная перерисовка в цикле кадров потребляет 5-10% CPU даже в простое, что неприемлемо для трекера привычек.

### Нативный Win32 API

* Хорошо, потому что нулевые сторонние зависимости и минимальный вес `.exe`.
* Плохо, потому что 100% привязка к платформе Windows (полная потеря кроссплатформенности под Linux).
* Плохо, потому что крайне трудоёмкая разработка кастомного календаря и стилизованных карточек (увеличивает трудоёмкость на 80+ часов).

## Дополнительная информация

Решение согласовано с Заказчиком в ходе интервью по архитектуре SDD. Документация классов GUI представлена в секции 3.1 SDD.
