# Контроль доступности внешнего API и уведомление о сбое

Связанные требования в SRS: REQ-FUNC-001, REQ-FUNC-002, REQ-FUNC-003, REQ-FUNC-004.

## Формулировка

Система должна позволять пользователю добавить внешний API (название, адрес эндпоинта, интервал проверки), автоматически и регулярно проверять его доступность, показывать текущий статус на главной панели и уведомлять пользователя на экране и по электронной почте, если API стал недоступен, а также когда он снова заработал.

## Обоснование

Команды, которые используют внешние API, часто узнают о сбое поставщика только от своих клиентов. Автоматическая проверка со статусом на одном экране сокращает это время. Уведомление только после нескольких неуспешных проверок подряд защищает от ложных тревог из-за кратковременных сбоев сети.

## Критерии приёмки

* **Добавление:** пользователь может добавить API, указав название, адрес эндпоинта и интервал проверки; пустое название и некорректный адрес отклоняются с понятным сообщением.
* **Интервал:** допустимый интервал от 1 до 60 минут, по умолчанию 5 минут.
* **Критерий недоступности:** проверка неуспешна, если ответ не получен за 10 секунд либо получен HTTP-код 5xx.
* **Статус на панели:** для каждого API отображаются статус (работает / недоступен), время последней проверки и время ответа.
* **Уведомление о сбое:** после трёх неуспешных проверок подряд создаётся одно уведомление на экране и одно письмо, не позднее чем через одну минуту после третьей проверки.
* **Без повторов:** пока API остаётся недоступным, новые уведомления о том же сбое не создаются.
* **Восстановление:** после первой успешной проверки недоступного API отправляется уведомление о возобновлении работы.
* **Сбой почты:** если почтовый сервис недоступен, уведомление остаётся на экране.

## Метод верификации

Тест | Демонстрация

* **Тест:** проверить граничные значения интервала (0, 1, 60, 61 минута); смоделировать эндпоинт с кодом 500 и эндпоинт, не отвечающий более 10 секунд, и убедиться, что статус меняется на «недоступен»; убедиться, что после двух неуспешных проверок уведомления нет, а после третьей оно одно; проверить уведомление о восстановлении и поведение при недоступной почте.
* **Демонстрация:** показать на тестовом эндпоинте путь от добавления API до получения уведомления и возврата в статус «работает».

## Дополнительная информация

* **Макеты:** главная панель и форма добавления API (`srs/img/`, будут добавлены).
* **Зависимости:** почтовый сервис; проверяемые эндпоинты должны быть доступны из интернета.
* **Вне этого требования:** учёт расходов, бюджет и лимиты.
