# Дополнительные спецификации EventPass

Версия 0.1. Автор: Овсяник А.Н. Дополняют функциональные требования SRS; нумерация совпадает с таблицей 3.5 SRS.

## 1. Удобство использования
- REQ-INT-001: основные сценарии выполняются не более чем за 5 действий; интерфейс на русском языке.
- Состояние ошибки (противоречивые фильтры, нехватка мест, истечение брони) сообщается текстом рядом с элементом (`role="alert"`), а не только цветом.
- Пустой результат поиска сопровождается подсказкой «Измените условия поиска или сбросьте фильтры».

## 2. Адаптивность и совместимость
- REQ-INT-002: корректное отображение от 360 px (mobile-first); Chrome, Firefox, Safari, Edge последних версий.

## 3. Производительность
- REQ-PERF-001: загрузка каталога не более 2 с при 1000 событий; отклик фильтрации не более 1 с.
- Фильтрация и постраничная выдача выполняются за один проход по списку событий на клиенте; размер страницы — 6 событий.

## 4. Безопасность
- REQ-SEC-001: HTTPS; пароли хранятся только в виде хеша; авторизация по токену; посетитель видит только свои заказы и билеты.
- Срок брони определяется только временем сервера: клиент вычисляет остаток как `expiresAt − (now + offset)`, где `offset = serverTime − clientNow`; перевод часов на компьютере не продлевает бронь.
- Текст из данных (названия событий) выводится средствами React с автоматическим экранированием.

## 5. Надёжность
- REQ-REL-001: купленный билет доступен в истории покупок при любом повторном входе.
- Бронь не продлевается при изменении состава корзины; по истечении 15 минут сервер возвращает места в продажу и отвечает на запросы по брони кодом 410.
- Нехватка мест при бронировании возвращается кодом 409; клиент показывает сообщение и сохраняет прежнее состояние корзины.

## 6. Сопровождаемость
- REQ-MAINT-001: раздельные слои UI и API-клиента; покрытие модульными тестами ключевой логики корзины не менее 70 %.
- Бизнес-логика (`src/domain`) не зависит от React и тестируется без браузера; серверная часть заменяется имитацией `MockApi` с подставляемыми часами.
- Денежные суммы хранятся целыми числами в минимальных единицах (копейки).

## 7. Ограничения реализации
- React + TypeScript (клиент), REST/JSON, компонент отображения QR-кода (SRS 3.1).
- Реальная оплата и нативные мобильные приложения вне границ версии 0.1.
