# DoneDeal — дополнительные спецификации

Документ дополняет use-case модель требованиями, которые не привязаны к отдельному прецеденту. Идентификаторы NFR согласованы с `sdd/sdd.md` (раздел 6.2).

## 1. Функциональные аспекты, общие для системы

| ID | Требование | Приоритет |
|---|---|---|
| SS-F-01 | Доступ к функциям определяется ролью пользователя по матрице из раздела 2 | 10 |
| SS-F-02 | Каждая платёжная операция записывается в журнал: время, задача, сумма, статус, ключ идемпотентности (NFR-04) | 30 |
| SS-F-03 | Ошибки внешних сервисов не должны приводить к потере данных: при сбое шлюза статус задачи не меняется | 10 |

## 2. Матрица ролей

| Действие | Заказчик | Исполнитель | Администратор |
|---|---|---|---|
| Создать, опубликовать задачу | да | нет | нет |
| Просмотреть кандидатов, выбрать, одобрить, вернуть | да | нет | нет |
| Откликнуться, сдать работу | нет | да | нет |
| Оставить отзыв | да | да | нет |
| Открыть спор | да | да | нет |
| Разрешить спор | нет | нет | да |

## 3. Удобство использования

| ID | Требование | Приоритет |
|---|---|---|
| SS-U-01 | Создание задачи занимает не более 5 минут (NFR-03, BO-4) | 20 |
| SS-U-02 | Обязательные поля формы отмечены символом «*», ошибки показываются рядом с полем | 30 |
| SS-U-03 | Интерфейс на русском языке; суммы в BYN, даты в формате ДД.ММ.ГГГГ | 40 |

| ID | Требование | Приоритет |
|---|---|---|

| SS-R-03 | Резервная копия базы данных создаётся ежедневно | 30 |

## 8. Ограничения проектирования

- Архитектура — модульный монолит на React, Node.js, PostgreSQL (ADR-0001).
- Платежи — внешний шлюз в тестовом режиме с готовой платёжной страницей (ADR-0002).
- Срок проекта — 5 итераций по 2 недели; команда — 1 старший разработчик и junior-разработчик на итерациях 3–4.

## 9. Интерфейсные требования

| Интерфейс | Требование |
|---|---|
| Пользовательский | Chrome, Firefox, Edge последних версий; адаптивная вёрстка от 360 px (NFR-06) |
| Программный (API) | REST, формат JSON, аутентификация по сессии |
| Платёжный шлюз | Создание платежа, webhook-уведомления, ключ идемпотентности в каждом запросе |
| Почтовый сервис | Отправка писем по SMTP или API; повторная отправка при сбое |

## 10. Правовые требования

- При регистрации пользователь соглашается на обработку персональных данных.
- Хранятся только email и хеш пароля; лишние персональные данные не собираются.
- Реальные денежные операции в рамках проекта не выполняются.
