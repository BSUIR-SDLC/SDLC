# Дополнительные спецификации QRGate

Версия 1.0 · 05.11.2026 · Гамза Г. А.

Документ дополняет [модель вариантов использования](../uml/use-cases.md): фиксирует требования, которые
не относятся к одному прецеденту, а действуют для всей системы или для нескольких прецедентов
(классификация FURPS+). Каждая позиция ссылается на требования [SRS 0.3](../srs/srs-qrgate.md), которые
она уточняет, и на прецеденты, к которым применяется. Бизнес-правила (BR) используются в потоках
событий прецедентов вместо повторения условий. Термины — по [глоссарию](glossary.md).

## 1. Бизнес-правила

| ID | Правило | Источник | Прецеденты |
|----|---------|----------|------------|
| BR-01 | Решение ALLOW выдаётся только если пройдены все проверки цепочки в порядке: подпись → существование → отзыв/версия → срок → зона → anti-passback → вместимость. Код отказа — первая нарушенная проверка | REQ-FUNC-004 | UC-10 |
| BR-02 | Номер пропуска сотрудника имеет вид `P-NNNNNN`, гостя — `G-NNNNNN`; номер уникален и не используется повторно | REQ-FUNC-003, 008 | UC-03, UC-04, UC-11 |
| BR-03 | Гостевой пропуск действует не дольше одних суток; пропуск сотрудника — не дольше 1 года с возможностью продления | Интервью, вопрос 7 | UC-04, UC-11 |
| BR-04 | При строгом anti-passback нельзя войти, уже находясь внутри, и выйти, не находясь внутри. Выход при блокировке по вместимости разрешён всегда | REQ-FUNC-006, 010 | UC-10 |
| BR-05 | Отзыв и перевыпуск увеличивают версию пропуска; QR прежней версии получает `DENY_REVOKED` | REQ-FUNC-005 | UC-04, UC-10 |
| BR-06 | Повторное распознавание того же токена в течение 3 с на одном сканере игнорируется | REQ-FUNC-002 | UC-02 |
| BR-07 | Ежедневно в 04:00 по времени объекта присутствие всех пропусков обнуляется; ручной сброс требует указания причины | REQ-FUNC-013 | UC-09 |
| BR-08 | Фото владельца можно загрузить только при отметке о согласии на обработку персональных данных | REQ-FUNC-015, CON-5 | UC-12 |
| BR-09 | События журнала старше 12 месяцев удаляются автоматически; данные владельца удаляются по запросу вместе с фото | REQ-SEC-005-2 | UC-13, UC-04 |
| BR-10 | Контролёр работает только на точках прохода, назначенных ему администратором, и видит данные только своего объекта | REQ-SEC-001 | UC-01, UC-08 |
| BR-11 | Каждая проверка, ручной ввод и сброс счётчика фиксируются в журнале с автором и временем | REQ-FUNC-004, 013 | UC-02, UC-03, UC-09 |

## 2. Функциональность (сквозные требования)

| ID | Требование | Уточняет | Прецеденты |
|----|------------|----------|------------|
| SUP-F-01 | Аудит: все изменяющие операции администратора (выпуск, отзыв, импорт, изменение настроек, сброс) пишутся в журнал действий с автором и временем | REQ-FUNC-011, 013 | UC-04, UC-07, UC-09, UC-11 |
| SUP-F-02 | Аутентификация: все прецеденты, кроме UC-13, требуют действующей сессии; при её истечении клиент переходит на экран входа без потери введённых в форму данных панели | REQ-FUNC-001 | Все, кроме UC-13 |
| SUP-F-03 | Авторизация по ролям: контролёр — UC-01 – UC-03, UC-08 своего объекта; администратор — UC-01, UC-04 – UC-12 | REQ-SEC-001 | Все |
| SUP-F-04 | Локализация: интерфейс, сообщения об ошибках и причины отказа — на русском языке; даты в формате `ДД.ММ.ГГГГ ЧЧ:ММ` по часовому поясу объекта | CON-6 | Все |

## 3. Удобство использования (Usability)

| ID | Требование | Уточняет |
|----|------------|----------|
| SUP-U-01 | Обучение контролёра работе со сканером — не более 10 минут; все действия сканера выполняются одной рукой | 2.4 SRS, REQ-INT-001 |
| SUP-U-02 | Решение различимо без чтения текста: цвет + форма значка + звук + вибрация при отказе | REQ-INT-002 |
| SUP-U-03 | Контраст и размер целей нажатия — WCAG 2.1 AA, кнопки сканера ≥ 48 px | REQ-COMP-003 |
| SUP-U-04 | Любое отказное или ошибочное состояние сканера содержит одну крупную кнопку дальнейшего действия («Следующий», «Повторить») | REQ-FUNC-007, REQ-REL-001 |

## 4. Надёжность (Reliability)

| ID | Требование | Уточняет |
|----|------------|----------|
| SUP-R-01 | Fail-closed: при отсутствии ответа сервера 5 с сканер не показывает ALLOW | REQ-REL-001, ADR-0006 |
| SUP-R-02 | Решение, событие журнала и изменение счётчика — одна транзакция; публикация в WebSocket только после фиксации | REQ-REL-002, ADR-0004 |
| SUP-R-03 | Доступность в часы работы объекта 07:00 – 22:00 — не ниже 99,5 %; ежедневная резервная копия БД, хранение 14 дней | REQ-AVAIL-001 |
| SUP-R-04 | Автоматическое переподключение панели к WebSocket с задержкой 1 – 30 с | REQ-REL-003 |

## 5. Производительность (Performance)

| ID | Требование | Уточняет |

| SUP-P-02 | От распознавания QR до карточки решения — не более 1,5 с (p95, 4G) | REQ-PERF-002 |
| SUP-P-03 | 10 000 активных пропусков, 50 сканеров, 20 панелей, 2 млн событий | REQ-PERF-003 |
| SUP-P-04 | Список эвакуации на 400 человек — не более 2 с; импорт 500 строк CSV — не более 10 с | REQ-FUNC-014, 008 |

## 6. Сопровождаемость (Supportability)

| ID | Требование | Уточняет |
|----|------------|----------|
| SUP-S-01 | TypeScript `strict`, ESLint без ошибок, покрытие модулей `qr-token` и `validation` ≥ 80 % строк | REQ-MAINT-001 |
| SUP-S-02 | Логи JSON без токенов и ФИО; метрики Prometheus | REQ-OBS-001 |
| SUP-S-03 | UML-модели поведения хранятся как текст PlantUML рядом с кодом и перестраиваются скриптом; таблица переходов автомата сканера в коде совпадает с диаграммой состояний (проверяется тестом) | ADR-0009, ADR-0010 |
| SUP-S-04 | Модуль подписи токена — отдельный пакет без зависимостей от Express и БД | 3.5.5 SRS |
