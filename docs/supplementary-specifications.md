# Дополнительные спецификации проекта GitPulse

## 1. Назначение и область применения
Настоящий документ содержит дополнительные (нефункциональные, системные и кросс-сценарные) спецификации для кроссплатформенной десктопной утилиты **GitPulse**. Документ дополняет спецификацию требований (`SRS`), модель прецедентов и диаграммы динамического поведения, описывая требования, которые распространяются на несколько сценариев использования или определяют качество работы системы в целом.

## 2. Функциональные правила сквозного действия
* **SUPP-FUNC-01 (Безопасность `Dirty`-репозиториев):** Репозитории со статусом `Dirty` (наличие незакоммиченных изменений в рабочем дереве или индексе) не должны автоматически выбираться для очистки, а их очистка без явного подтверждения пользователя блокируется для предотвращения потери несохранённых изменений.
* **SUPP-FUNC-02 (Целевые каталоги сборочных артефактов):** Система анализирует и удаляет только явно заданные каталоги сборочных артефактов и кэшей зависимостей (включая `bin`, `obj`, `node_modules`, `target`, `build`, `cmake-build-debug`), не затрагивая каталоги `.git`, исходный код и конфигурационные файлы проекта.
* **SUPP-FUNC-03 (Контроль порогового объёма артефактов):** Система вычисляет суммарный объём обнаруженных артефактов и активирует индикатор/уведомление о превышении порогового значения: в базовом контуре действует порог 500 МБ в интерфейсе, а по итогам переговоров с заказчиком фоновый режим с уведомлением при достижении 5 ГБ включается в текущий релиз без сдвига жёсткого дедлайна за счёт подключения Junior-разработчика.
* **SUPP-FUNC-04 (Подтверждение массовой очистки):** Перед безвозвратным удалением артефактов выбранных репозиториев система запрашивает у пользователя подтверждение в модальном окне с отображением состава целей и итогового объёма освобождаемого места.

## 3. Требования к качеству обслуживания (QoS)
* **SUPP-PERF-01 (Отзывчивость интерфейса):** Длительные операции обхода файловой системы, обращения к `Git CLI` и удаления каталогов выполняются асинхронно в фоновых задачах, не блокируя поток отрисовки пользовательского интерфейса.
* **SUPP-PERF-02 (Время сканирования и отмена):** Сканирование типового дерева каталогов объёмом до 5 000 папок должно укладываться в установленные лимиты производительности (не более 15 секунд в базовом сценарии) и поддерживать прерывание по запросу пользователя (`CancellationToken`).
* **SUPP-REL-01 (Устойчивость к ошибкам файловой системы и прав доступа):** При возникновении ошибок доступа, блокировки отдельных файлов сторонними процессами или некорректном пути система не должна аварийно завершать работу; ошибки фиксируются, а обработка остальных доступных элементов продолжается.
* **SUPP-REL-02 (Проверка зависимости Git CLI):** При отсутствии `Git CLI` или несоответствии версии минимальному требованию (`>= 2.40`) система должна корректно обрабатывать ошибку выполнения команды и информировать пользователя вместо аварийного падения или выдачи ложного статуса.
* **SUPP-AVAIL-01 (Автономная работа):** Весь основной функционал аудита и очистки выполняется локально без подключения к сети Интернет и без зависимости от облачных сервисов.
* **SUPP-OBS-01 (Журналирование операций и ошибок):** Результаты операций очистки и возникающие исключения/ошибки ввода-вывода записываются в локальный файл журнала `gitpulse.log` для последующей диагностики.

## 4. Ограничения платформы, окружения и архитектуры
* **SUPP-PLAT-01 (Кроссплатформенность):** Приложение разрабатывается на C# / .NET 9 с использованием Avalonia UI и должно корректно запускаться и работать на Windows 10/11, Linux и macOS с нормализацией разделителей путей под целевую ОС.
* **SUPP-ARCH-01 (Разделение слоёв и хранение состояния):** Сохраняется слоистая архитектура (`GitPulse.UI`, `GitPulse.Core`, `GitPulse.Infrastructure`) с паттерном MVVM и взаимодействием с `Git CLI` через дочерние процессы; данные сканирования хранятся в оперативной памяти без развёртывания внешней СУБД.
* **SUPP-DIST-01 (Портативность поставки):** Поставка осуществляется в портативном формате (`Self-contained` / без обязательного инсталлятора) в рамках прав текущего пользователя ОС.

## 5. Стандарты, сопровождение и трассируемость
* **SUPP-COMP-01 (Соответствие стандартам):** Документация и проектные артефакты оформляются с учётом СТП 01–2024 БГУИР и актуальных версий нотаций моделирования (`SysML v2` для статических структурных моделей ЛР №3–№4, `UML / PlantUML` для моделей динамического поведения ЛР №5).
* **SUPP-MAINT-01 (Управление изменениями и разделение работ):** Изменения вносятся через ветки Git и Pull Request с ведением истории версий в документах; рутинные задачи (часть UI-компонентов и вспомогательное логирование) могут распределяться на Junior-разработчика при сохранении критических модулей за ведущим разработчиком для удержания дедлайна.
* **SUPP-TRACE-01 (Трассировка):** Требования настоящего документа соотносятся с `REQ-FUNC-*`, `REQ-PERF-*`, `REQ-SEC-*`, `REQ-REL-*`, `REQ-AVAIL-*`, `REQ-OBS-*` из `SRS`, представлениями `VIEW-*` из `SDD` и решениями `ADR-001`–`ADR-003`.
