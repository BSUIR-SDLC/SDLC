# Выбор локального JSON-хранилища на базе Jackson вместо реляционной СУБД SQLite

## Контекст и постановка задачи

Приложению WineVault требуется надежное хранилище для каталога вин, настроек погреба и истории дегустаций. Коллекция среднестатистического пользователя насчитывает от 50 до 1 000 бутылок. Необходимо выбрать технологию хранения данных, исключающую сложные внешние зависимости и драйверы native C-библиотек, сохраняющую полную приватность данных и гарантирующую работу без доступа к сети Internet (Air-gap безопасность).

## Драйверы решения

* Простота резервного копирования и синхронизации: пользователь должен иметь возможность скопировать файл коллекции на флешку или просмотреть его в текстовом редакторе.
* Отсутствие нативных платформозависимых бинарников: библиотека JDBC SQLite требует нативных библиотек `.dll` / `.dylib` / `.so`, что усложняет запуск на разных ОС.
* Быстродействие при объемах коллекции до 5 000 записей: чтение и запись всего каталога должны укладываться в 10–20 мс (согласно `REQ-NFR-PERF-001`).
* Выполнение требований `REQ-NFR-SEC-001` (автономность) и `REQ-NFR-PORT-001` (переносимость).

## Рассмотренные варианты

* **Вариант 1:** Реляционная СУБД SQLite через SQLite-JDBC и ORM Hibernate/JPA.
* **Вариант 2:** Файловое JSON-хранилище на базе библиотеки **Jackson Databind (POJO serialization)**.
* **Вариант 3:** Встраиваемая база данных H2 Database (файл `.mv.db`).

## Итог решения

Выбранный вариант: **«Вариант 2: Файловое JSON-хранилище Jackson»**, поскольку для каталогов частных коллекций (до нескольких тысяч объектов) хранение в структурированном JSON-файле обеспечивает наивысшую переносимость, не требует настройки SQL-схем, миграций Liquibase/Flyway и полностью исключает риск несовместимости платформенных native-библиотек.

### Последствия

* **Положительные:**
  * Файл `wine_cellar.json` открывается и читается любым текстовым редактором, что высоко ценится заказчиком.
  * Нулевые накладные расходы на инициализацию пула соединений БД; ускорение холодного старта приложения до < 800 мс.
  * Абсолютная переносимость между Windows, Linux и macOS.
* **Отрицательные:**
  * При модификации одной записи сохраняется весь массив вин (полная перезапись), однако при объеме базы до 1–2 Мб это занимает менее 15 мс на современных SSD/NVMe.
* **Нейтральные:**
  * Необходимость реализации атомарной перезаписи файлов для предотвращения повреждения структуры JSON при сбое питания (см. ADR-0003).
