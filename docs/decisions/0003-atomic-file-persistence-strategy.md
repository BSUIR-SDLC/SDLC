# Обеспечение надежности хранения через двухфазную атомарную замену файлов (Atomic Move)

## Контекст и постановка задачи

При использовании локального JSON-хранилища (`wine_cellar.json`) прямая перезапись файла несет в себе критический риск: в случае внезапного аварийного выключения питания ПК, разряда батареи ноутбука или сбоя процесса во время выполнения метода `FileOutputStream.write()` исходный файл коллекции может оказаться обрезанным до 0 байт или содержать поврежденный синтаксис JSON, что приведет к безвозвратной потере реестра винного погреба.

## Драйверы решения

* Гарантия сохранности данных пользователя при аппаратных и программных сбоях (`REQ-NFR-REL-001`).
* Исключение промежуточных поврежденных состояний файла хранилища.
* Автоматическое создание ежедневной резервной копии перед мутирующими операциями (`REQ-NFR-REL-002`).

## Рассмотренные варианты

* **Вариант 1:** Прямая перезапись `new FileWriter("wine_cellar.json")` без предварительной буферизации.
* **Вариант 2:** Запись во временный файл `wine_cellar.tmp` с последующим вызовом нативного метода операционной системы `Files.move(..., StandardCopyOption.ATOMIC_MOVE, REPLACE_EXISTING)`.
* **Вариант 3:** Логирование транзакций через Write-Ahead Logging (WAL-журналирование).

## Итог решения

Выбранный вариант: **«Вариант 2: Двухфазная атомарная замена файлов (Atomic Move) с резервированием»**, поскольку этот подход на уровне файловой системы POSIX/NTFS гарантирует, что операция замены ссылки на inode/дескриптор файла происходит неделимо (атомарно). Пользовательский файл никогда не окажется в полузаписанном виде.

### Последствия

* **Положительные:**
  * Полная защита базы данных вин от повреждений при обесточивании ПК.
  * Если в процессе сериализации Jackson возникнет исключение (OutOfMemory или ошибка валидации), старый файл `wine_cellar.json` останется нетронутым.
  * Реализация укладывается в стандартные средства JDK `java.nio.file.Files` без усложнения кодовой базы.
* **Отрицательные:**
  * В редких файловых системах (например, сетевые папки NFS/SMB) операция `ATOMIC_MOVE` может не поддерживаться, поэтому в коде предусмотрен fallback на стандартное копирование с последующим удалением.
* **Нейтральные:**
  * Требуется дополнительное свободное дисковое пространство в размере одного размера базы данных (несколько килобайт) в момент сохранения.

## Связанные требования и артефакты
* SRS: `REQ-NFR-REL-001`, `REQ-NFR-REL-002`.
* SDD: Раздел 3.3 (Interaction View) и Раздел 3.4 (Information View).
