# ADR-0006: Семантика доставки: at-least-once, Idempotency-Key, 5 попыток, затем недоставленные

- Статус: accepted
- Дата: 12.11.2026
- Принимающий решение: М. Н. Дешко (архитектор)
- Связанные требования: REQ-REL-002, REQ-FUNC-007, REQ-FUNC-015

## Контекст и постановка проблемы

Требуется выбрать решение: семантика доставки: at-least-once, Idempotency-Key, 5 попыток, затем недоставленные.

## Драйверы решения

- BG-2: нет молчаливых потерь
- REQ-REL-002: повтор не повторяет эффект
- REQ-FUNC-007: повторы с растущей паузой

## Рассмотренные варианты

- At-most-once (без повторов)
- At-least-once с Idempotency-Key
- Exactly-once через двухфазную фиксацию

## Решение

Выбран вариант: **At-least-once с Idempotency-Key**. Единственный практичный вариант без потерь; ключ равен идентификатору доставки, поэтому повторы и ручной повтор из списка недоставленных безопасны.

## Последствия

- Хорошо: никакие действия не пропадают
- Хорошо: ручной повтор (F22) использует тот же ключ
- Плохо: получатели без поддержки ключа могут получить дубль

## Подтверждение

тесты сбоев 5xx, тайм-аут, 4xx; тест повтора с тем же ключом.

## Плюсы и минусы вариантов

### At-most-once (без повторов)

- Хорошо: нет дублей
- Плохо: действие теряется при любом сбое

### At-least-once с Idempotency-Key

- Хорошо: нет потерь
- Хорошо: дубль не меняет результат у получателя
- Плохо: получатель должен понимать ключ

### Exactly-once через двухфазную фиксацию

- Хорошо: строгая гарантия
- Плохо: эмулятор и система уведомлений не поддерживают протокол
