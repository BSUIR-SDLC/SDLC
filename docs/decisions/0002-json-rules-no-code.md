# ADR-0002: Правила – JSON-документы с проверкой по JSON Schema, без исполнения кода

- Статус: accepted
- Дата: 12.11.2026
- Принимающий решение: М. Н. Дешко (архитектор)
- Связанные требования: REQ-FUNC-004, REQ-FUNC-005, REQ-SEC-004, REQ-INT-005

## Контекст и постановка проблемы

Требуется выбрать решение: правила – JSON-документы с проверкой по JSON Schema, без исполнения кода.

## Драйверы решения

- REQ-SEC-004 и CON-5: правила не исполняют код
- CON-3: правила хранятся как JSON
- BG-1: оператор пишет правила сам
- REQ-INT-005: формат описан схемой

## Рассмотренные варианты

- Собственный JSON-формат и JSON Schema (Ajv)
- JsonLogic
- Выражения на JavaScript в песочнице
- Политики OPA / Rego

## Решение

Выбран вариант: **Собственный JSON-формат и JSON Schema**. Единственный вариант, который одновременно исключает исполнение кода и остаётся понятным оператору; ограниченный набор из 10 операторов покрывает сценарии стенда.

## Последствия

- Хорошо: безопасность по построению
- Хорошо: схему можно использовать в редакторе и при импорте
- Плохо: сложные условия ограничены набором операторов

## Подтверждение

30 тестов правил на схему; тест, что пакет rule-dsl не импортирует child_process, vm и eval.

## Плюсы и минусы вариантов

### Собственный JSON-формат и JSON Schema (Ajv)

- Хорошо: нет исполнения кода
- Хорошо: ошибки с путём до поля
- Хорошо: формат прозрачен для оператора
- Плохо: операторы и пути нужно реализовать самим (пакет rule-dsl)

### JsonLogic

- Хорошо: готовая библиотека
- Плохо: неудобная префиксная запись
- Плохо: слабая проверка структуры действий

### Выражения на JavaScript в песочнице

- Хорошо: максимальная гибкость
- Плохо: риск выхода из песочницы
- Плохо: нарушает REQ-SEC-004

### Политики OPA / Rego

- Хорошо: зрелый язык политик
- Плохо: избыточно для задачи
- Плохо: отдельный язык и сервис
