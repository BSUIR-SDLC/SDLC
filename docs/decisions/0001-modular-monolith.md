# ADR-0001: Модульный монолит на Node.js 20 и Fastify

- Статус: accepted
- Дата: 12.11.2026
- Принимающий решение: М. Н. Дешко (архитектор)
- Связанные требования: REQ-REL-001, REQ-MAINT-001

## Контекст и постановка проблемы

Требуется выбрать решение: модульный монолит на Node.js 20 и Fastify.

## Драйверы решения

- REQ-REL-001: сохранение события и постановка действий в очередь – в одной транзакции
- CON-1: стек Node.js и TypeScript
- AS-5: один–два разработчика
- REQ-MAINT-001: чёткие границы модулей

## Рассмотренные варианты

- Модульный монолит
- Микросервисы (приём, движок, доставка)
- Serverless-функции

## Решение

Выбран вариант: **Модульный монолит**. Только он даёт простую атомарность приёма события и постановки действий (REQ-REL-001) при минимальной операционной нагрузке.

## Последствия

- Хорошо: атомарность без распределённых транзакций
- Хорошо: один образ для процессов api и worker
- Плохо: нужен линтер границ модулей
- Плохо: масштабирование только вертикальное (допустимо по AS-3)

## Подтверждение

правило eslint-plugin-boundaries в CI; интеграционный тест транзакции приёма события.

## Плюсы и минусы вариантов

### Модульный монолит

- Хорошо: одна транзакция БД
- Хорошо: простое развёртывание и отладка
- Плохо: границы модулей держатся только дисциплиной

### Микросервисы (приём, движок, доставка)

- Хорошо: независимое масштабирование
- Плохо: распределённые транзакции
- Плохо: лишняя инфраструктура для 1–2 разработчиков

### Serverless-функции

- Хорошо: нет серверов
- Плохо: холодный старт мешает ответу ≤ 200 мс
- Плохо: очередь доставки приходится строить отдельно
