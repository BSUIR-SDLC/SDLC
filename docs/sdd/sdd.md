# Описание дизайна программного обеспечения

**Для веб-приложения Medora**  
**Версия:** 0.2 (согласованный MVP)  
**Подготовил:** Зелень А. И.  
**Дата:** 2026-11-09

## 1. Назначение

SDD фиксирует архитектуру Medora после двух раундов согласования с заказчиком.

## 2. Границы MVP

Входит: справочник лекарств, расписание, ежедневные отметки, остатки, карточка лекарства, напоминания в UI, базовая история, **экспорт PDF-отчёта (REQ-FUNC-009)**.

Не входит в MVP: полноценный Web Push и расширенные фильтры истории (REQ-FUNC-005 — post-MVP).

## 3. Компоненты

Medicine, Schedule, Intake, Stock, Notifications (UI), History, MedicineCard, **PdfReport**.

## 4. Архитектура

Клиент → Spring Boot API → PostgreSQL.  
PDF формируется на backend; junior участвует в UI/шаблоне (см. ADR-003).

## 5. Связанные решения

- ADR-001 — Spring Boot + PostgreSQL  
- ADR-002 — Web Push вне MVP  
- ADR-003 — junior для PDF без сдвига дедлайна
