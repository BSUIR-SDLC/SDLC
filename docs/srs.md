# Спецификация бизнес-требований

## Ambient Reader — читалка книг с эмбиентом

Версия 1.0 · 05.11.2026 · Автор: Голов Александр Сергеевич

## 1. Введение

### 1.1 Назначение

Документ фиксирует бизнес-цели, границы и проверяемые требования к desktop-приложению Ambient Reader. Документ предназначен для заказчика, разработчика и тестировщика и описывает, **что** должна делать система.

### 1.2 Область применения

Ambient Reader помогает читателю хранить личную библиотеку, читать электронные книги и включать атмосферные звуки, привязанные автором к отдельным частям произведения. В первую версию входят локальные книги EPUB/FB2/TXT, библиотека, закладки, прогресс и аудиоэмбиент. Онлайн-магазин, социальные функции и автоматическая генерация музыки не входят в границы релиза.

### 1.3 Термины

| Термин | Значение |
|---|---|
| Эмбиент | Фоновая аудиодорожка, сопровождающая чтение части книги |
| Часть | Глава или иной именованный фрагмент книги |
| Закладка | Сохранённая позиция чтения с заметкой пользователя |

## 2. Обзор продукта

### 2.1 Бизнес-цели

1. Повысить вовлечённость читателя за счёт соответствующей атмосферы.
2. Дать автору простой способ связывать аудио с главами книги.
3. Обеспечить приватное чтение без обязательной регистрации и передачи библиотеки в облако.

### 2.2 Пользователи

- **Читатель** — добавляет книги, читает, управляет громкостью и сохраняет прогресс.
- **Автор/редактор** — подготавливает книгу и указывает аудио для её частей.

### 2.3 Функции продукта

- импорт и удаление книг;
- отображение библиотеки и продолжение чтения;
- навигация по частям книги;
- воспроизведение, пауза, перемотка и регулировка громкости эмбиента;
- автоматическое переключение аудио при переходе в другую часть;
- закладки и восстановление позиции;
- сохранение настроек локально.

### 2.4 Ограничения и допущения

Приложение является desktop-приложением для Windows/Linux, работает без обязательного подключения к интернету, использует локальные файлы EPUB, FB2, TXT, MP3 и OGG. Аудиофайл, указанный в метаданных части, может отсутствовать — в этом случае чтение продолжается без звука.

## 3. Требования

### 3.1 Пользовательский интерфейс

Главный экран содержит библиотеку слева, область текста по центру и панель управления эмбиентом снизу. В верхней панели доступны импорт книги, поиск и настройки. Макет приведён в `ambient-reader-mockup.png`.

### 3.2 Функциональные требования

| ID | Требование | Критерий приёмки |
|---|---|---|
| REQ-FUNC-001 | Система должна импортировать EPUB, FB2 и TXT из локального файла. | После выбора корректного файла книга появляется в библиотеке. |
| REQ-FUNC-002 | Система должна отображать список книг с названием, автором и прогрессом. | Для каждой добавленной книги видны эти три поля. |
| REQ-FUNC-003 | Система должна открывать книгу и показывать её текст по частям. | Пользователь может перейти к следующей и предыдущей части. |
| REQ-FUNC-004 | Система должна воспроизводить эмбиент выбранной части в форматах MP3/OGG. | Нажатие «Play» запускает звук, «Pause» останавливает его. |
| REQ-FUNC-005 | Система должна автоматически менять аудиодорожку при переходе между частями. | При переходе к части с другим эмбиентом воспроизводится новый файл. |
| REQ-FUNC-006 | Система должна предоставлять регулировку громкости и отключение звука. | Изменение ползунка меняет громкость без остановки чтения. |
| REQ-FUNC-007 | Система должна сохранять последнюю позицию чтения. | После повторного открытия книги отображается сохранённая часть и позиция. |
| REQ-FUNC-008 | Система должна позволять создавать и удалять закладки. | Закладка восстанавливает сохранённую позицию. |
| REQ-FUNC-009 | Система должна корректно обрабатывать отсутствующий аудиофайл. | Показывается уведомление, текст остаётся доступным для чтения. |

### 3.3 Качество обслуживания

- **REQ-PERF-001:** открытие книги объёмом до 50 МБ должно занимать не более 3 секунд на целевом компьютере.
- **REQ-REL-001:** сбой аудиоплеера не должен завершать процесс чтения.
- **REQ-SEC-001:** пользовательские книги, прогресс и закладки должны храниться локально и не отправляться на внешний сервер без отдельного согласия.
- **REQ-USE-001:** основные действия чтения должны быть доступны не более чем за два клика.

## 4. Верификация

Все функциональные требования проверяются демонстрацией и тестированием. Требования производительности проверяются измерением времени открытия книги, требования безопасности — инспекцией сетевых запросов и каталога локальных данных.
