# Моделирование динамического поведения системы «Кабинет фрилансера» (UML)

## 1. Модель вариантов использования (Use Case Diagram)

### 1.1 Описание действующих лиц (Actors)
* **Фрилансер (Freelancer):** Основной пользователь системы, осуществляющий поиск проектов по навыкам, отправку откликов, загрузку файлов-результатов и запрос оплаты.
* **Заказчик (Client):** Внешний участник процесса, принимающий сданный файл-результат, подтверждающий выплату вознаграждения и оставляющий рейтинг с отзывом.
* **Платёжный шлюз (Payment Gateway):** Внешняя системная служба, обеспечивающая проведение расчётов и зачисление средств на баланс фрилансера.

### 1.2 PlantUML-код диаграммы вариантов использования
```plantuml
@startuml
left to right direction
actor "Фрилансер" as Freelancer
actor "Заказчик" as Client
actor "Платёжный шлюз" as PaymentSys

rectangle "Система «Кабинет фрилансера»" {
  usecase "UC-01: Просмотр и фильтрация\nзадач по навыкам" as UC1
  usecase "UC-02: Подача отклика\nна задачу" as UC2
  usecase "UC-03: Загрузка файла-\nрезультата" as UC3
  usecase "UC-04: Требование оплаты\nза выполненную задачу" as UC4
  usecase "UC-05: Оценка работы и\nоставление отзыва" as UC5
  usecase "UC-06: Валидация состояния\nи наличия файла" as UC6
  usecase "UC-07: Просмотр баланса\nи истории транзакций" as UC7
}

Freelancer --> UC1
Freelancer --> UC2
Freelancer --> UC3
Freelancer --> UC4
Freelancer --> UC7

UC4 ..> UC6 : <<include>>
UC3 ..> UC6 : <<include>>
UC5 ..> UC4 : <<extend>>

UC4 --> PaymentSys
Client --> UC5
@enduml
