# Дополнительные спецификации TourReview

## Спецификация акторов

| Актор | Роль |
|---|---|
| Турист | Ищет туристические места, оставляет отзывы, оценки, фото и жалобы на недопустимый контент. |
| Арендодатель | Добавляет объекты аренды и отвечает на отзывы о своих объектах. |
| Модератор | Обрабатывает очередь жалоб, скрывает недопустимый контент и блокирует нарушителей. |

## Спецификация прецедентов

### UC-01. Создание отзыва
- **Актор:** Турист
- **Описание:** Турист оставляет отзыв (оценка 1–5, текст, опциональное фото) о месте.
- **Предусловия:** Пользователь авторизован и не заблокирован; место существует.
- **Поток событий (основной):** 1) Турист открывает карточку места → 2) Нажимает «Оставить отзыв» → 3) Вводит оценку, текст, при необходимости прикрепляет фото → 4) Нажимает «Сохранить» → 5) Система валидирует данные, сохраняет фото в `photos/`, вставляет запись в `reviews` → 6) Система пересчитывает `avg_rating` и `review_count` для места → 7) Система отображает отзыв в карточке и обновляет рейтинг.
- **Альтернативные потоки:**
    - 5a. Невалидные данные (пустой текст, оценка вне 1–5) → сообщение об ошибке, возврат к шагу 3.
    - 5b. Ошибка записи в БД → сообщение об ошибке, введённые данные не теряются.
- **Постусловия:** Отзыв сохранён и виден; рейтинг места обновлён.

### UC-02. Просмотр среднего рейтинга
- **Актор:** Турист
- **Описание:** Турист видит средний рейтинг и число отзывов в карточке места.
- **Предусловия:** Место существует.
- **Поток событий:** 1) Турист открывает карточку → 2) Система запрашивает `AVG(rating)` и `COUNT(reviews)` → 3) Отображает значения.
- **Постусловия:** Значения соответствуют данным БД.

### UC-03. Подача жалобы
- **Актор:** Турист
- **Описание:** Пользователь жалуется на отзыв/фото с указанием причины.
- **Предусловия:** Пользователь авторизован и не заблокирован.
- **Поток событий:** 1) Открывает отзыв → 2) «Пожаловаться» → 3) Выбирает причину → 4) Система создаёт `Complaint` → 5) Жалоба попадает в очередь модерации.
- **Постусловия:** Жалоба в очереди.

### UC-04. Ответ на отзыв
- **Актор:** Арендодатель
- **Описание:** Арендодатель отвечает на отзыв об объекте.
- **Предусловия:** Арендодатель авторизован; отзыв относится к его объекту.
- **Поток событий:** 1) Открывает отзыв → 2) Нажимает «Ответить» → 3) Вводит текст → 4) Система сохраняет `Reply` → 5) Ответ отображается под отзывом.
- **Альтернатива:** 4a. Ошибка БД → сообщение, данные не теряются.
- **Постусловия:** Ответ сохранён и отображается.

### UC-05. Обработка жалобы
- **Актор:** Модератор
- **Описание:** Модератор просматривает очередь жалоб и принимает решение.
- **Предусловия:** Модератор авторизован.
- **Поток событий:** 1) Открывает очередь → 2) Выбирает жалобу → 3) Принимает решение «Скрыть» (переход к UC-06) или «Оставить» → 4) Система меняет статус → 5) Жалоба закрывается.
- **Постусловия:** Решение по жалобе принято.

### UC-06. Скрыть контент
- **Актор:** Не имеет прямого актора (включается из UC-05)
- **Описание:** Система скрывает недопустимый контент (отзыв/фото).
- **Предусловия:** Модератор выбрал решение «Скрыть» в UC-05.
- **Поток событий:** 1) Система меняет статус отзыва на «Скрыт» → 2) Отзыв становится невидимым для других пользователей.
- **Постусловия:** Контент скрыт.

### UC-07. Блокировка пользователя
- **Актор:** Модератор
- **Описание:** Модератор блокирует нарушителя.
- **Предусловия:** Модератор авторизован; пользователь существует.
- **Поток событий:** 1) Открывает профиль → 2) «Заблокировать» → 3) Система ставит `is_blocked = true`.
- **Постусловия:** Пользователь не может оставлять отзывы/жалобы.

### UC-08. Редактирование своего отзыва
- **Актор:** Турист
- **Описание:** Пользователь редактирует ранее оставленный отзыв (изменяет текст, оценку или фото).
- **Предусловия:** Пользователь авторизован; отзыв принадлежит этому пользователю.
- **Поток событий (основной):** 1) Пользователь открывает свой отзыв в карточке места → 2) Нажимает «Редактировать» → 3) Вносит изменения в оценку, текст или прикрепляет новое фото → 4) Нажимает «Сохранить» → 5) Система валидирует новые данные → 6) Система обновляет запись в таблице `reviews` (при необходимости заменяет файл фото в `photos/`) → 7) Система пересчитывает `avg_rating` и `review_count` для места → 8) Система отображает обновлённый отзыв.
- **Альтернативные потоки:**
    - 5a. Невалидные данные → сообщение об ошибке, возврат к шагу 3.
    - 6a. Ошибка записи в БД → сообщение об ошибке, старые данные не теряются.
- **Постусловия:** Отзыв обновлён; рейтинг места пересчитан.

### UC-09. Добавление места аренды
- **Актор:** Арендодатель
- **Описание:** Арендодатель создаёт новый объект для отдыха (место аренды).
- **Предусловия:** Пользователь авторизован и обладает правами арендодателя.
- **Поток событий (основной):** 1) Пользователь нажимает «Добавить место» → 2) Вводит название, описание и при необходимости прикрепляет фото → 3) Нажимает «Сохранить» → 4) Система валидирует данные и сохраняет фото в файловое хранилище → 5) Система вставляет запись в таблицу `places` → 6) Место отображается в общем списке.
- **Альтернативные потоки:**
    - 4a. Невалидные данные (пустое название, недопустимый формат фото) → сообщение об ошибке, возврат к шагу 2.
    - 5a. Ошибка записи в БД → сообщение об ошибке, введённые данные не теряются.
- **Постусловия:** Новое место сохранено и доступно для просмотра и отзывов.
