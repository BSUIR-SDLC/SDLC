# ADR-002: Реляционное хранилище

- **Статус:** принято для учебной версии
- **Дата:** 2026-10-22

## Контекст
В FocusFlow есть связанные сущности: пользователь и его цели, привычки и отметки выполнения, команды и членства. Важны ограничения целостности и согласованные изменения.

## Решение
Использовать реляционную базу данных и слой доступа к данным с репозиториями/DAO. Конкретную СУБД следует согласовать с технологическим стеком SRS ЛР3.

## Рассмотренные альтернативы
1. Документная БД — гибкая схема, но связи и ограничения целостности требуют дополнительной логики.
2. Хранение в файлах — не подходит для конкурентного доступа и связанных транзакционных изменений.

## Последствия
- Положительные: внешние ключи, уникальные ограничения, транзакции и структурированные запросы.
- Отрицательные: изменения схемы требуют миграций.
- Требование: схема и миграции должны храниться под контролем версий.
