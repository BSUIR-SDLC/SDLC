# ADR-004: REST API для клиент-серверного взаимодействия

- **Статус:** принято для учебной версии
- **Дата:** 2026-10-22

## Контекст
Веб-клиент должен обращаться к серверным функциям по единому, документируемому интерфейсу.

## Решение
Использовать HTTP REST API с ресурсными маршрутами, стандартными методами HTTP и JSON для типовых запросов/ответов. Для выгрузки CSV использовать отдельный endpoint с корректным типом содержимого.

## Рассмотренные альтернативы
1. GraphQL — гибкий выбор полей, но добавляет схему и дополнительную сложность.
2. Прямой доступ клиента к базе — недопустим по соображениям безопасности и архитектурного разделения.

## Последствия
- Положительные: понятные маршруты, единообразные коды HTTP и удобное тестирование.
- Отрицательные: необходимо документировать контракты и согласовывать изменения API.
- Требование: изменения маршрутов и ответов должны сопровождаться обновлением документации и тестов.
