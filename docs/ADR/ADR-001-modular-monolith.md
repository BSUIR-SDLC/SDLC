# ADR-001: Модульный монолит

- **Статус:** принято для учебной версии
- **Дата:** 2026-10-22

## Контекст
FocusFlow содержит несколько связанных предметных областей: цели, привычки, календарь, заметки и команды. Для учебного проекта важно обеспечить понятную архитектуру без чрезмерной инфраструктурной сложности.

## Решение
Использовать модульный монолит: одно серверное приложение, разделённое на модули с чёткими обязанностями и интерфейсами.

## Рассмотренные альтернативы
1. Микросервисы — независимое развёртывание, но больше сетевой, эксплуатационной и тестовой сложности.
2. Монолит без модульных границ — проще начать, но сложнее поддерживать ответственность компонентов.

## Последствия
- Положительные: проще локальная разработка, транзакции и развёртывание; единый проект проще тестировать.
- Отрицательные: масштабирование модулей отдельно ограничено.
- Условие пересмотра: рост нагрузки или независимых команд разработки, оправдывающий выделение отдельных сервисов.
