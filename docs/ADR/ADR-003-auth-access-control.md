# ADR-003: Серверная аутентификация и проверка доступа

- **Статус:** принято для учебной версии
- **Дата:** 2026-10-22

## Контекст
Система хранит личные цели, привычки и заметки, а также командные данные. Скрытие элементов интерфейса само по себе не защищает API от несанкционированного доступа.

## Решение
Проверять аутентификацию и авторизацию на сервере для каждого защищённого запроса. Для личных сущностей проверять владельца; для командных действий — членство и роль пользователя.

## Рассмотренные альтернативы
1. Проверять права только на клиенте — недостаточно безопасно.
2. Разрешать доступ по знанию идентификатора сущности — создаёт риск доступа к чужим данным.

## Последствия
- Положительные: единая политика безопасности и тестируемые правила доступа.
- Отрицательные: проверки должны последовательно применяться во всех защищённых обработчиках.
- Проверки: негативные тесты для попыток читать/изменять чужие данные и выполнять действия без нужной роли.
