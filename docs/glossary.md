# Глоссарий проекта RuleHook

Версия 1.0 (лабораторная работа №5). Единые термины для SRS, SDD, ADR, UML-моделей и кода.
Колонка «В коде» – имя сущности, типа или поля; «Где» – прецеденты (uml/use-cases.md), требования SRS, бизнес-правила (docs/supplementary-specification.md) или решения ADR.

## 1 Предметная область

| Термин | Определение | В коде | Где |
|---|---|---|---|
| Эмулятор | Внешняя система, имитирующая оборудование: отправляет события вебхуками и принимает команды от RuleHook | `emulator` (цель), источник `emulator-1` | UC-02, UC-09 |
| Система уведомлений | Внешняя система, принимающая уведомления (Telegram, SMTP, Webhook-шлюз) по HTTP POST | `notifier` (цель) | UC-09 |
| Источник | Зарегистрированный отправитель вебхуков со своим секретом подписи; имеет идентификатор в URL приёма | `Source`, `sourceId` | UC-02, UC-05 |
| Событие | Факт, о котором сообщил источник: идентификатор, тип, полезная нагрузка | `WebhookEvent` | UC-02, UC-10 |
| Вебхук | HTTP POST-запрос источника на адрес `/hooks/{sourceId}`, содержащий одно событие | `handleWebhook` | UC-02, REQ-INT-001 |
| Тип события | Строка-категория события, например `sensor.temperature`; по ней выбираются правила | `event.type` | UC-10 |
| Полезная нагрузка | JSON-объект с данными события (значения датчиков, идентификатор устройства) | `payload` | UC-10, UC-12 |
| Устройство | Объект эмулятора, к которому относится событие и которому может быть отправлена команда | `payload.deviceId` | UC-09 |
| Команда | Тело POST-запроса к эмулятору, меняющее состояние устройства, например `shutdown` | `action.body` | UC-09 |
| Уведомление | Тело POST-запроса к системе уведомлений с текстом для человека | `action.body.text` | UC-09 |

## 2 Правила и сопоставление

| Термин | Определение | В коде | Где |
|---|---|---|---|
| Правило | JSON-документ «когда – тогда»: условия по событию и действия при их выполнении | `Rule` | UC-03, ADR-0002 |
| Условие (when) | Логическое выражение из сравнений и операторов all / any / not, вложенность до 3 уровней | `rule.when` | UC-10, REQ-FUNC-005 |
| Оператор сравнения | Одна из 10 операций: eq, ne, gt, gte, lt, lte, in, contains, regex, exists | `op` | UC-10 |
| Путь к полю | Адрес значения в событии в синтаксисе JSONPath-lite, например `$.payload.value` | `path` | UC-10 |
| Действие (then) | Описание исходящего POST: цель, путь, тело с подстановками | `Action` | UC-09 |
| Шаблон | Подстановка `{{payload.x}}` в путь или тело действия значением из события | `renderPath` | UC-09, F08 |
| Приоритет правила | Число; правила проверяются по возрастанию приоритета, при равенстве – по id | `rule.priority` | BR-04 |
| Версия правила | Число, увеличиваемое при каждом сохранении; в журнале фиксируется версия, которая сработала | `rule.version` | UC-03, UC-11 |
| Совпадение | Запись о том, что событие удовлетворило условию правила | `RuleMatch` | UC-10 |
| Пробный прогон (dry-run) | Проверка правила на примере события без сохранения и без отправки действий | `dryRun` | UC-12, REQ-FUNC-008 |
| Пояснение (explain) | Результат вычисления каждого условия правила: какое сравнение выполнено, какое нет | `explain` | UC-04, UC-12 |
| Импорт правил | Загрузка массива правил из файла с отчётом по каждой записи | `importRules` | UC-11, REQ-FUNC-010 |

## 3 Доставка и защита

| Термин | Определение | В коде | Где |
|---|---|---|---|
| Цель | Зарегистрированный администратором получатель действий: имя и базовый URL из списка разрешённых хостов | `Target` | UC-06, REQ-INT-003 |
| Доставка | Одна попытка выполнить одно действие одного совпадения; имеет статус и счётчик повторов | `Delivery` | UC-09 |
| Статус доставки | Состояние автомата доставки: QUEUED, SENDING, RETRY_WAIT, PAUSED, DELIVERED, SKIPPED, FAILED, CANCELLED, PURGED | `DeliveryState` | state-delivery.puml |
| Очередь доставки | Таблица доставок в PostgreSQL, из которой воркеры забирают задачи `FOR UPDATE SKIP LOCKED` | `delivery` | ADR-0004 |
| Воркер доставки | Процесс, выполняющий исходящие POST-запросы из очереди | `DeliveryWorker` | UC-09 |
| Повтор (retry) | Повторная отправка после временной ошибки (408, 429, 5xx, сеть); всего не более 5 попыток (ADR-0006) | `RETRYABLE_ERROR` | BR-09, REQ-REL-001 |
| Экспоненциальная пауза | Ожидание 2^n секунд перед n-м повтором: 2, 4, 8, 16 с | `backoffMs` | BR-09 |
| Недоставленное действие | Доставка в статусе FAILED, ожидающая ручного повтора | `failed` | UC-08, REQ-FUNC-015 |
| Ручной повтор (replay) | Возврат недоставленного действия в очередь с тем же ключом идемпотентности | `REPLAY` | UC-08, BR-10 |
| Ключ идемпотентности | Заголовок `Idempotency-Key` исходящего запроса, равный id доставки; получатель по нему отбрасывает дубли | `Idempotency-Key` | BR-10, ADR-0006 |
| At-least-once | Гарантия «не менее одного раза»: действие может прийти дважды, но не потеряется | – | ADR-0006 |
| Счётчик переходов (X-Hop) | Заголовок, который RuleHook увеличивает в исходящих запросах и читает во входящих; ограничивает цепочки правил | `hop` | BR-06, ADR-0008 |
| Пауза повторного срабатывания (cooldown) | Время, в течение которого правило не срабатывает повторно для того же источника | `cooldownSec` | BR-07 |
| Автоотключение | Выключение правила при превышении 20 срабатываний за 60 с с записью причины | `RATE_EXCEEDED` | UC-14, BR-08 |
| Петля правил | Цепочка, в которой действие правила порождает событие, снова запускающее правила | – | UC-14, ADR-0008 |
| Глобальная пауза | Режим, в котором события принимаются и сопоставляются, а доставки не отправляются | `GLOBAL_PAUSE` | UC-07, BR-12 |

## 4 Пользователи, безопасность и эксплуатация

| Термин | Определение | В коде | Где |
|---|---|---|---|
| Пользователь | Любое лицо с учётной записью веб-консоли; обобщает оператора и администратора | `User` | UC-01 |
| Оператор | Роль: правила, журнал, повтор недоставленных | `operator` | UC-03, UC-04, UC-08 |
| Администратор | Роль: всё, что оператор, плюс источники, цели, пауза, пользователи | `admin` | UC-05 – UC-07 |
| Планировщик (время) | Неличностный актёр: запускает доставку по таймерам и очистку данных по расписанию | `Scheduler` | UC-09, UC-13 |
| Подпись вебхука | HMAC-SHA256 от сырого тела запроса с секретом источника в заголовке `X-RuleHook-Signature` | `sign`, `verify` | BR-01, ADR-0003 |
| Секрет источника | Случайная строка, известная источнику и RuleHook | `source.secret` | UC-05 |
| Ротация секрета | Замена секрета; старый действует ещё 24 ч | `activeSecrets` | UC-05, BR-01 |
| Блокировка входа | Запрет входа на 15 минут после 5 неудачных попыток подряд | `applyLoginAttempt` | UC-01 |
| Сессия | Аутентифицированный сеанс пользователя длительностью до 12 ч | `session` | UC-01 |
| Журнал обработки | История событий, совпадений и доставок с пояснениями | `journal` | UC-04, REQ-FUNC-011 |
| Срок хранения | 30 суток для событий и доставок, до 90 суток для недоставленных | `RETENTION_EXPIRED` | UC-13, BR-11 |
| Маскирование | Замена значений секретов и полей из списка маскирования на `***` в журнале | `mask` | BR-11, REQ-SEC-005-2 |
| Лимит запросов | Ограничение числа вебхуков в секунду от источника | `rateLimit` | REQ-SEC-002 |
| Дубликат | Повторно доставленное событие с уже известным id; принимается ответом 200 без повторной обработки | `DUPLICATE` | BR-03 |
