# Глоссарий проекта IoTPanel

| Термин / Акроним | Определение в контексте проекта IoTPanel |
|---|---|
| **Устройство (IoT Device)** | Виртуальный или физический узел в системе с уникальным идентификатором `device_id`, передающий метрики и принимающий управляющие команды. |
| **Телеметрия (Telemetry)** | Поток JSON-пакетов с показаниями датчиков (`temperature` в °C, `motion` в формате 0/1), передаваемый от эмулятора по протоколу WebSocket. |
| **Правило автоматизации (Automation Rule)** | Декларативный JSON-объект вида «Устройство -> Метрика -> Условие -> Действие», формируемый через 4-шаговый конструктор без ручного редактирования кода. |
| **Движок правил (Rule Engine)** | Серверный компонент на Node.js + Express, оценивающий входящую телеметрию по активным правилам, отправляющий команды `/command` и тревожные оповещения. |
| **Команда (`/command`)** | Управляющий HTTP POST-запрос на изменение состояния исполнительного механизма устройства (например, `COOLING_ON`, `HEATER_ON`, `ALARM_ON`). |
| **Fail-Closed блокировка** | Защитный режим интерфейса: при потере связи с устройством (отсутствие heartbeat > 5 с) устройство переводится в статус `OFFLINE`, а тумблер управления блокируется. |
| **Тестовый прогон (Dry-Run)** | Режим симуляции срабатывания правила для проверки отправки Telegram/Webhook-уведомления без физического переключения реле устройства. |
| **Квитирование тревоги (Acknowledge)** | Явное подтверждение оператором получения критического предупреждения в красном баннере интерфейса с записью в журнал аудита. |
