# Глоссарий проекта EventPass

Версия 0.1. Автор: Овсяник А.Н. Основание: SRS (`srs/srs.md`), SDD (`sdd/sdd.md`).

| Термин | Определение | Где используется |
|--------|-------------|------------------|
| EventPass | Web-приложение посетителя: клиентская часть платформы продажи билетов на мероприятия | весь проект |
| Посетитель | Пользователь приложения: ищет события, покупает билеты, хранит и предъявляет их | SRS 3.2, UC-01…UC-11 |
| Событие | Мероприятие (концерт, спектакль, матч, выставка, конференция) с датой, местом и типами билетов | REQ-FUNC-002, 004 |
| Категория | Тип события: концерт, театр, спорт, выставка, конференция | REQ-FUNC-003 |
| Каталог | Постраничный список событий с названием, датой, местом, категорией и минимальной ценой | REQ-FUNC-002 |
| Фильтр | Условие отбора событий: город, дата, категория, диапазон цен; условия объединяются по «И» | REQ-FUNC-003 |
| Поиск | Отбор событий по подстроке в названии без учёта регистра | REQ-FUNC-003 |
| Карточка события | Страница события: описание, место, типы билетов, цены, число свободных мест | REQ-FUNC-004 |
| Тип билета | Категория мест на событии (например, «Партер», «Ложа») с ценой и числом свободных мест | `TicketType` |
| Корзина | Набор выбранных билетов до оформления заказа | REQ-FUNC-005 |
| Позиция корзины | Строка корзины: тип билета события и количество | `CartLine` |
| Бронь (резерв) | Временное закрепление мест за посетителем на 15 минут по часам сервера | FEAT-02 |
| Таймер брони | Обратный отсчёт оставшегося времени брони; считается по времени сервера | FEAT-02 |
| Истечение брони | Событие «время брони вышло»: места возвращаются в продажу, корзина очищается | UC-12 |
| Overselling | Продажа одного места нескольким посетителям; предотвращается серверной бронью | SRS, переговоры ЛР4 |
| Промокод | Код, дающий скидку на сумму корзины (процент или фиксированная сумма) | FEAT-09 |
| Заказ | Подтверждённая покупка: состав корзины, сумма, статус, дата | REQ-FUNC-006, 008 |
| Имитация оплаты | Подтверждение заказа без реального платёжного шлюза | SRS 3.6 |
| Билет | Электронный документ на одно место с данными события, типом, местом и статусом | REQ-FUNC-007 |
| QR-код | Двумерный код билета, который отображается на экране и считывается на входе | REQ-FUNC-007, ADR-001 |
| Статус билета | «Действителен» или «Возвращён» | REQ-FUNC-007 |
| История покупок | Список заказов посетителя с датой, составом, суммой и статусом | REQ-FUNC-008 |
| Mock SMTP | Тестовый почтовый сервер для проверки отправки писем без реальной доставки | FEAT-03 |
| REST API | Интерфейс серверной части платформы: события, брони, заказы, билеты | SRS 3.1 |
| JWT | Токен авторизации, хранимый на клиенте | FEAT-07 |
| Актёр | Внешнее по отношению к системе лицо или система, взаимодействующая с ней | UML, use-case |
| Прецедент (вариант использования) | Описание последовательности действий, приводящей к значимому для актёра результату | UML, `docs/use-cases.md` |
| Поток событий | Пошаговое описание прецедента: основной, альтернативные и ошибочные потоки | `docs/use-cases.md` |
| MoSCoW | Метод приоритизации требований: Must, Should, Could, Won't | SRS 2.2 |
| ADR | Протокол архитектурного решения | `adr/` |
| SDD | Документ описания проектирования ПО по IEEE 1016-2009 | `sdd/sdd.md` |
