# Глоссарий проекта GitPulse

| Термин (EN / RU) | Определение и контекст использования |
| :--- | :--- |
| **GitPulse** | Кроссплатформенное настольное приложение для аудита локальных Git-репозиториев и безопасной очистки сборочных артефактов и кэшей зависимостей. Работает автономно в локальной файловой системе без обращения к внешним сетевым сервисам. |
| **Локальный Git-репозиторий (Git Repository)** | Каталог на локальном накопителе пользователя, содержащий служебную директорию `.git` и отслеживаемый системой контроля версий Git. Является основной единицей анализа и отображения в таблице приложения. |
| **Сборочные артефакты (Build Artifacts)** | Временные и генерируемые при компиляции или установке зависимостей каталоги и файлы (например, `bin`, `obj`, `node_modules`, `target`, `.gradle`, `__pycache__`), подлежащие расчёту объёма и безопасному удалению. |
| **Корневая директория сканирования (Target Root Path)** | Выбранный пользователем путь на локальном диске, с которого начинается рекурсивный обход подкаталогов для поиска Git-репозиториев и подсчёта размера артефактов. |
| **Статус репозитория (Git Status)** | Состояние рабочего дерева и индекса Git-репозитория, определяемое через `Git CLI`. В системе различаются состояния `Clean` (нет незафиксированных изменений) и `Dirty` (имеются неотслеживаемые или изменённые файлы). |
| **Чистый репозиторий (Clean)** | Статус репозитория, при котором рабочее дерево не содержит незакоммиченных изменений. Репозитории со статусом `Clean` разрешены к выделению и автоматической очистке артефактов по умолчанию. |
| **Грязный репозиторий (Dirty)** | Статус репозитория с незакоммиченными изменениями. Для предотвращения случайной потери данных выбор таких репозиториев для очистки ограничен либо требует явного подтверждения. |
| **Активная ветка (Active Branch)** | Имя текущей ветки Git (`HEAD`), в которой находится локальный репозиторий на момент сканирования (например, `main`, `develop`, `feature/v2`). |
| **Последний коммит (Last Commit)** | Дата и время последней фиксации изменений в текущей ветке репозитория, отображаемые пользователю для оценки актуальности проекта. |
| **Порог размера артефактов (Artifact Threshold)** | Пороговое значение суммарного объёма найденных артефактов, при превышении которого система активирует визуальное предупреждение (`ThresholdWarningVisible`) о необходимости освободить место на диске. |
| **Безопасная очистка (Safe Cleanup)** | Операция удаления выбранных каталогов сборочных артефактов с предварительным диалогом подтверждения, сохраняющая исходный код, историю коммитов (`.git`) и конфигурационные файлы проекта. |
| **MainWindow** | Главное окно графического интерфейса приложения на базе Avalonia UI, содержащее панель выбора пути, сводку сканирования, таблицу репозиториев и панель запуска очистки. |
| **ConfirmDialog** | Модальное диалоговое окно подтверждения операции очистки, отображающее список выбранных репозиториев и суммарный объём освобождаемого дискового пространства перед удалением файлов. |
| **MainViewModel** | Модель представления главного окна в паттерне MVVM, хранящая состояние интерфейса (`TargetPath`, `Repositories`, `SelectedSizeFormatted`, `ThresholdWarningVisible`) и команды `ScanDiskCommand` и `CleanArtifactsCommand`. |
| **RepositoryInfo** | Модель данных отдельного найденного Git-репозитория, содержащая его имя, путь, активную ветку, статус (`GitStatus`), размер артефактов в байтах, дату последнего коммита и флаги выбора (`IsSelected`, `CanSelect`). |
| **ScanResult** | Агрегированный результат выполнения сканирования директории, содержащий коллекцию найденных объектов `RepositoryInfo`, общий объём артефактов (`TotalArtifactsBytes`) и флаг превышения порога (`IsThresholdExceeded`). |
| **DiskScannerService** | Сервис слоя `GitPulse.Core` (реализующий `IScanningService`), выполняющий асинхронный рекурсивный поиск Git-репозиториев и расчёт размера артефактов с поддержкой отмены через `CancellationToken`. |
| **CleanupService** | Сервис слоя `GitPulse.Core` (реализующий `ICleanupService`), выполняющий удаление артефактов для выбранных репозиториев, подсчёт освобождённого места и журналирование операций. |
| **ThresholdChecker** | Компонент слоя `GitPulse.Core`, проверяющий превышение допустимого порога суммарного объёма сборочных артефактов (500 МБ) и формирующий сигнал предупреждения для пользовательского интерфейса[cite: 27, 28, 30]. |
| **GitCliExecutor** | Компонент слоя `GitPulse.Infrastructure` (реализующий `IGitCliExecutor`), взаимодействующий с внешним процессом `Git CLI` (версии не ниже `2.40`) для получения текущей ветки, статуса и даты последнего коммита. |
| **OsFileSystemProvider** | Компонент слоя `GitPulse.Infrastructure` (реализующий `IFileSystem`), инкапсулирующий операции обхода каталогов, подсчёта размера файлов и удаления директорий в локальной файловой системе. |
| **FileLogger** | Компонент слоя `GitPulse.Infrastructure` (реализующий `ILogger`), записывающий события сканирования, удаления артефактов и ошибки ввода-вывода в локальный журнал работы приложения. |
| **MVVM (Model-View-ViewModel)** | Архитектурный паттерн разделения ответственности в слое `GitPulse.UI`, обеспечивающий связь представлений (`MainWindow`, `ConfirmDialog`) с логикой представления (`MainViewModel`) через механизм привязки данных (`DataBinding`). |
| **Avalonia UI** | Кроссплатформенный .NET UI-фреймворк, используемый для построения графического интерфейса `GitPulse` под Windows, Linux и macOS. |
| **Git CLI** | Консольный клиент системы контроля версий Git (требуемая минимальная версия `>= 2.40`), вызываемый приложением в качестве внешнего процесса для инспекции состояния репозиториев. |
| **SRS (Software Requirements Specification)** | Спецификация требований к программному обеспечению GitPulse, определяющая функциональные и нефункциональные требования и пользовательский интерфейс. |
| **SDD (Software Design Document)** | Документ описания проектирования ПО GitPulse (по стандарту IEEE 1016), фиксирующий архитектуру слоёв, модель данных и динамическое поведение системы. |
| **ADR (Architecture Decision Record)** | Запись архитектурного решения, документирующая выбор ключевых технологий, паттернов и механизмов взаимодействия компонентов системы с обоснованием альтернатив. |
