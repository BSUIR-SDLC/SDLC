# Глоссарий проекта EasyTicket

Версия 0.1. Подготовил: Питковский В.В. Дата: 12.11.2026. Используется в SRS (`srs/srs.md`), SDD (`sdd/sdd.md`) и UML-моделях (`docs/use-cases.md`, `docs/uml.md`).

| Термин | Определение | Где используется |
|--------|-------------|------------------|
| Администратор | Сотрудник зала, управляющий афишей, просматривающий статистику продаж и отменяющий брони | SRS 2.4, UC-09, UC-10, UC-12 |
| Афиша | Список предстоящих активных мероприятий, доступный покупателю на главной странице | UC-01, REQ-FUNC-001 |
| Бизнес-правило | Утверждение о бизнесе, которому должна соответствовать система (например, одно место принадлежит одному покупателю) | SRS 1.2 |
| Бронь (резервирование) | Временное закрепление места за покупателем на 10 минут до оформления заказа | UC-03, REQ-FUNC-005 |
| Время жизни брони (TTL) | Срок действия брони, 10 минут с момента добавления первого места в корзину | REQ-FUNC-005 |
| Выручка | Сумма цен проданных и не возвращённых билетов мероприятия, в BYN | UC-10, REQ-FUNC-013 |
| Заказ | Набор мест одного мероприятия, оформленный на один email, с уникальным номером вида `ORD-ГГГГ-NNNNNN` | UC-04, REQ-FUNC-006 |
| Заказчик | Сторона, формулирующая бизнес-цели и согласующая требования, сроки и стоимость (в проекте — напарник) | SRS, `docs/communication.md` |
| Зал | Помещение с фиксированной схемой мест, в котором проходят мероприятия | SDD DV-004 |
| Категория мест | Группа мест зала с общей ценой (например, VIP, партер, балкон) | REQ-FUNC-002 |
| Контролёр | Сотрудник, проверяющий билеты на входе по QR-коду | SRS 2.4, UC-08 |
| Корзина | Набор выбранных покупателем мест (от 1 до 10) до оформления заказа | REQ-FUNC-004 |
| Мероприятие | Спектакль, концерт или иное событие, на которое продаются билеты; имеет статус «Черновик», «Активно» или «Завершено» | SRS 1.3 |
| Овербукинг | Продажа одного и того же места более чем одному покупателю; недопустима | SRS 1.3, ADR-0002 |
| Оплата (эмуляция) | Подтверждение заказа без обращения к платёжной системе; в версии 0.1 реальные платежи не выполняются | REQ-FUNC-006 |
| Outbox | Таблица исходящих писем, из которой фоновый обработчик отправляет почту с повторными попытками | ADR-0004 |
| Покупатель | Посетитель сайта, выбирающий места и оформляющий заказ без регистрации | SRS 2.4 |
| Подпись (HMAC) | Код аутентификации, вычисляемый от данных билета секретным ключом; защищает QR-код от подделки | ADR-0003 |
| Прецедент (вариант использования) | Последовательность действий системы в ответ на событие, инициированное актёром, с наблюдаемым результатом | `docs/use-cases.md` |
| Актёр | Роль, которую внешний пользователь или система играет по отношению к проектируемой системе | `docs/use-cases.md` |
| Поток событий | Пошаговое описание выполнения прецедента: основной, альтернативные потоки и потоки ошибок | `docs/use-cases.md` |
| QR-код | Двумерный штрих-код билета, содержащий идентификаторы заказа, билета, мероприятия, место и подпись | REQ-FUNC-007 |
| Схема зала | Визуальное представление мест зала со статусами «Свободно», «Забронировано», «Продано» | REQ-FUNC-003 |
| Сотрудник (staff) | Общее название администратора и контролёра, проходящих вход по логину и паролю | REQ-FUNC-011 |
| Статус места | Состояние места для мероприятия: «Свободно», «Забронировано», «Продано» | `docs/uml.md` |
| Билет | Электронный документ на одно место с уникальным QR-кодом; имеет состояния «Выдан», «Использован», «Возвращён» | REQ-FUNC-007, REQ-FUNC-010 |
| Возврат билета | Отказ покупателя от неиспользованного билета не позднее чем за 24 часа до начала мероприятия | REQ-FUNC-015, UC-07 |
| Mock SMTP | Тестовый почтовый сервер, принимающий письма без доставки адресатам (порт 1025) | SRS 2.3 |
| Итерация | Период разработки длиной 2 недели, по итогам которого демонстрируется результат | `sdd/plan.md` |
