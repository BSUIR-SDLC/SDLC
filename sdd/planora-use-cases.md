# Модель вариантов использования Planora

Версия 1.1 · 22 ноября 2026 г.

Диаграмма: [исходник PlantUML](uml/use-cases.puml). Требования: [SRS Planora](../srs/planora-srs.md). Общие правила безопасности, валидации и сохранения приведены в [дополнительных спецификациях](planora-additional-specifications.md).

## Акторы

| Актор | Описание |
|---|---|
| Пользователь | Владелец аккаунта, который через браузер создаёт и просматривает личные планы. |

Администратор системы является операционной ролью SRS, но не участвует в пользовательских прецедентах первой версии: эксплуатационные действия выполняются за границами интерфейса Planora.

## Прецеденты

### UC-01 — Зарегистрироваться или войти

**Описание.** Пользователь создаёт учётную запись либо получает доступ к существующей личной рабочей области.

**Предусловия.** Для регистрации аккаунт с указанным адресом ещё не существует; для входа учётная запись уже зарегистрирована. Доступен сервер.

**Основной поток событий.** 1) Пользователь открывает регистрацию или вход. 2) Вводит контактные данные и пароль. 3) Клиент отправляет запрос. 4) Система проверяет данные, хеширует пароль при регистрации и создаёт аккаунт либо проверяет пароль при входе. 5) Система создаёт защищённую серверную сессию и открывает личный экран.

**Альтернативы.** Некорректные данные, занятый адрес или неверный пароль приводят к понятному сообщению; сессия не создаётся.

**Постусловия.** При успехе пользователь аутентифицирован; при отказе состояние аккаунта не меняется.

**Требования.** REQ-FUNC-001, REQ-SEC-001, REQ-SEC-004.

### UC-02 — Управлять задачами

**Описание.** Пользователь ведёт жизненный цикл собственной задачи: создание, просмотр, изменение, удаление и смена статуса.

**Предусловия.** Пользователь вошёл в систему.

**Основной поток событий.** 1) Пользователь открывает задачи или форму задачи. 2) Вводит название и, при необходимости, описание и срок. 3) Система проверяет данные и сохраняет запись с владельцем из сессии. 4) Пользователь может изменить данные, отметить задачу выполненной или вернуть её в активное состояние. 5) При удалении система исключает задачу из обычного просмотра.

**Альтернативы.** Невалидные поля показываются рядом с формой. При сетевой или серверной ошибке введённые значения остаются в форме. Запрос к чужой или отсутствующей записи отклоняется без раскрытия её наличия.

**Постусловия.** Изменение собственной задачи сохранено либо операция завершилась явной ошибкой без ложного подтверждения.

**Требования.** REQ-FUNC-002—005, REQ-FUNC-016, REQ-FUNC-018.

### UC-03 — Просмотреть планы по дате

**Описание.** Пользователь просматривает задачи на выбранный день, просроченные задачи и календарь событий в дневном или месячном виде.

**Предусловия.** Пользователь вошёл в систему; выбранная дата интерпретируется в часовом поясе его настроек.

**Основной поток событий.** 1) Пользователь открывает «Сегодня» или календарь. 2) Система получает только его записи. 3) Клиент отображает задачи выбранного дня и просроченные задачи, а события показывает в выбранном виде. 4) Пользователь может выбрать другую дату или переключить день/месяц.

**Альтернативы.** При пустом результате отображается пустое состояние; при ошибке загрузки предлагается повторить запрос.

**Постусловия.** Данные не изменяются; пользователь видит актуальный результат либо сообщение о недоступности.

**Требования.** REQ-FUNC-002, REQ-FUNC-006, REQ-FUNC-009, REQ-FUNC-013.

### UC-04 — Управлять событиями календаря

**Описание.** Пользователь создаёт и поддерживает собственные события с датой, временем и описанием.

**Предусловия.** Пользователь вошёл в систему.

**Основной поток событий.** 1) Пользователь открывает календарь и форму события. 2) Задаёт название, дату, начало, окончание и описание. 3) Система проверяет временной интервал и сохраняет событие с владельцем из сессии. 4) Пользователь просматривает или изменяет событие; ненужное событие можно удалить.

**Альтернативы.** Некорректный интервал или обязательные поля вызывают ошибку в форме; недоступность сервера не приводит к показу неподтверждённого успеха.

**Постусловия.** Событие сохранено и доступно в календаре владельца либо изменений нет и отображена причина отказа.

**Требования.** REQ-FUNC-007—009, REQ-FUNC-016, REQ-FUNC-018.

### UC-05 — Управлять заметками

**Описание.** Пользователь создаёт, изменяет и удаляет личные текстовые заметки.

**Предусловия.** Пользователь вошёл в систему.

**Основной поток событий.** 1) Пользователь открывает раздел заметок. 2) Создаёт заметку либо выбирает свою существующую запись. 3) Вводит или изменяет текст. 4) Система сохраняет изменения с текущим владельцем; пользователь при необходимости удаляет заметку.

**Альтернативы.** Ошибки валидации, сети или хранилища сообщаются без потери введённого текста; чужая запись недоступна.

**Постусловия.** Изменённая заметка хранится в пространстве пользователя либо операция отклонена без изменения данных.

**Требования.** REQ-FUNC-010, REQ-FUNC-016, REQ-FUNC-018.

### UC-06 — Найти записи

**Описание.** Пользователь ищет собственные записи по тексту названия или описания.

**Предусловия.** Пользователь вошёл в систему; введён поисковый запрос.

**Основной поток событий.** 1) Пользователь вводит текст. 2) Клиент запрашивает поиск. 3) Сервер ограничивает выборку владельцем сессии. 4) Клиент показывает совпадения и позволяет открыть запись.

**Альтернативы.** При отсутствии совпадений отображается пустой результат; при ошибке сервера показывается сообщение и возможность повторить запрос.

**Постусловия.** Данные не изменяются; результат поиска ограничен личными записями пользователя.

**Требования.** REQ-FUNC-012, REQ-FUNC-018, REQ-PERF-002.

### UC-07 — Настроить планер

**Описание.** Пользователь задаёт часовой пояс и предпочтительное представление календаря.

**Предусловия.** Пользователь вошёл в систему.

**Основной поток событий.** 1) Пользователь открывает настройки. 2) Выбирает часовой пояс и вид календаря. 3) Система проверяет и сохраняет предпочтения. 4) Последующие календарные представления используют сохранённые параметры.

**Альтернативы.** Неподдерживаемое значение не сохраняется; пользователю отображается ошибка.

**Постусловия.** Предпочтения сохранены для аккаунта либо прежние настройки остаются действующими.

**Требования.** REQ-FUNC-013, REQ-FUNC-016.

### UC-08 — Экспортировать и импортировать данные CSV

**Описание.** Пользователь выгружает собственные записи или переносит записи из файла CSV после просмотра результата разбора.

**Предусловия.** Пользователь вошёл в систему. Для экспорта у него могут быть записи; для импорта подготовлен CSV поддерживаемого формата.

**Основной поток событий.** 1) Для экспорта пользователь запрашивает файл; система формирует UTF-8 CSV только из его данных. 2) Для импорта пользователь выбирает файл. 3) Сервер проверяет формат и показывает число записей и ошибки до записи. 4) Пользователь подтверждает предпросмотр. 5) Система повторно проверяет контекст сессии и атомарно создаёт записи владельца.

**Альтернативы.** Пользователь отменяет импорт — данные не меняются. Ошибки формата показываются в предпросмотре. Ошибка записи приводит к откату всей транзакции. Недействительная сессия требует повторного входа.

**Постусловия.** Экспортный файл содержит только записи пользователя; импорт либо полностью сохранён после подтверждения, либо не изменил данные.

**Требования.** REQ-FUNC-019—020, REQ-SEC-002, REQ-SEC-005.

### UC-09 — Получить напоминание

**Описание.** Пользователь видит наступившее напоминание, пока работает в открытом приложении.

**Предусловия.** Пользователь вошёл в систему; для его задачи или события настроено напоминание; приложение открыто в момент наступления.

**Основной поток событий.** 1) Приложение загружает напоминания текущего пользователя. 2) При наступлении времени система показывает сообщение в интерфейсе. 3) Пользователь может открыть связанную задачу или событие.

**Альтернативы.** При закрытом приложении или сетевой недоступности доставка не гарантируется; напоминание не отображается как доставленное.

**Постусловия.** Напоминание показано в доступной пользовательской сессии; исходная запись не изменена.

**Требования.** REQ-FUNC-014—015.

### UC-10 — Выйти

**Описание.** Пользователь завершает текущую сессию и закрывает доступ к личной рабочей области.

**Предусловия.** Пользователь вошёл в систему.

**Основной поток событий.** 1) Пользователь выбирает выход. 2) Клиент отправляет запрос завершения сессии. 3) Сервер отзывает сессию и удаляет/инвалидирует cookie. 4) Клиент открывает экран входа.

**Альтернативы.** Если ответ сервера недоступен, интерфейс сообщает об ошибке завершения; защищённые API-запросы в любом случае проверяют действительность сессии.

**Постусловия.** При успехе текущая сессия недействительна; повторный доступ требует входа.

**Требования.** REQ-FUNC-017, REQ-SEC-004.
