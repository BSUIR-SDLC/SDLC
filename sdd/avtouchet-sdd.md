## 1. Введение {#1-introduction}

### 1.1 Назначение документа {#11-document-purpose}

Этот документ описывает, **как** устроен «Автоучёт» версии 0.1. Спецификация `srs.md` фиксирует, что программа делает. Здесь зафиксировано устройство, по которому это можно реализовать: пакеты, файл данных, формулы, экраны и принятые решения.

Документ читают:

* разработчик (автор и junior на блоке сравнения) — чтобы писать код в согласованных границах;
* заказчик — чтобы видеть, какие функции попали в релизы и почему срок именно такой;
* преподаватель — чтобы проследить требование SRS до представления и до ADR.

### 1.2 Область применения {#12-subject-scope}

Проектируется desktop-приложение «Автоучёт» 0.1: локальный журнал трат на один автомобиль и расчёт стоимости владения. Сети, сервера и платного API нет.

В дизайн версии 0.1 входит:

* карточка одного автомобиля и журнал расходов;
* проверка ввода до записи;
* период, итог, суммы пяти категорий, стоимость километра числом или фразой о нехватке пробега;
* сравнение двух периодов на том же главном экране;
* один JSON-файл в каталоге пользователя.

В дизайн версии 0.1 не входит:

* вторая машина, пароль, напоминания, карта заправок, оплата, выгрузка в налоговую;
* график расходов;
* фоновые потоки и синхронизация между компьютерами.

Системные требования ниже переводят SRS на язык устройства. Идентификатор `SYS-*` в этом документе не заменяет `REQ-*`: он показывает, какое проектное обязательство закрывает группу требований.

**Функциональные системные требования**

| ID | Обязательство дизайна | Закрывает |
|----|----------------------|-----------|
| SYS-F-01 | В памяти и в файле есть ровно одна карточка и список расходов. Добавление, правка и удаление проходят одну и ту же проверку полей | REQ-FUNC-001, REQ-FUNC-002, REQ-FUNC-004, REQ-FUNC-008 |
| SYS-F-02 | Список и сводка считаются по включительным границам дат. Период по умолчанию — текущий календарный месяц | REQ-FUNC-003, REQ-FUNC-005, REQ-INT-001 |
| SYS-F-03 | Цена километра считается в домене по всем категориям и не рисуется числом, если показаний пробега недостаточно | REQ-FUNC-006, REQ-POC-001 |
| SYS-F-04 | Сравнение двух периодов вычитает две уже посчитанные сводки и показывает разность на главном экране | REQ-FUNC-009, REQ-INT-005 |

Дизайн на эти изменения отвечает так: график не проектируется, SQLite не подключается, сравнение периодов добавляется блоком VIEW-006, а не новым приложением.

### 1.3 Определения, акронимы и сокращения {#13-definitions-acronyms-and-abbreviations}

| Term | Definition |
|------|------------|
| ADR | Architectural Decision Record — протокол одного архитектурного решения |
| BYN | Белорусский рубль. В домене сумма хранится в копейках, в JSON — десятичной строкой |
| EDT | Event Dispatch Thread — поток Swing, на котором живут окна версии 0.1 |
| JSON | Текстовый формат файла журнала |
| SDD | Software Design Description — этот документ |
| SRS | Software Requirements Specification — `srs.md` |
| Категория | Одно из значений FUEL, INSURANCE, TAX, REPAIR, OTHER. На экране — русские подписи |
| Копейка | 0,01 BYN, единица хранения суммы в домене, чтобы не копить ошибку двоичной дроби |
| Сводка | Итог периода, пять сумм категорий и цена километра либо признак нехватки пробега |

Термины предметной области, уже заданные в SRS (период, пробег, расход, стоимость владения, стоимость километра), здесь не переопределяются.

## 3. Проектные представления {#3-design-views}

### VIEW-001. Контекст

* **Title:** Пользователь и локальный файл.
* **Viewpoint:** Контекст.
* **Representation:**

```text
[ Владелец автомобиля ]
        | клавиатура, мышь, монитор
        v
+---------------- Автоучёт, один процесс Java ----------------+
|  окна Swing                                                 |
|  домен: карточка, расходы, сводка, сравнение                |
|  файл {user.home}/Avtouchet/ledger.json                     |
|  файл {user.home}/Avtouchet/avtouchet.log  (только сбои)    |
+-------------------------------------------------------------+
        внешние системы: нет
```

Актор один. Внешней системы нет: ни карты, ни банка, ни сервиса курсов. Варианты использования версии 0.1: вести карточку, записать и поправить расход, смотреть период, смотреть сравнение двух периодов.

* **More Information:** REQ-INT-004, REQ-SEC-001, REQ-DIST-001. Решение о стеке — ADR-0001.

### VIEW-002. Состав пакетов

* **Title:** Четыре пакета одного приложения.
* **Viewpoint:** Композиция.
* **Representation:**

| Пакет | Ответственность | Чего в пакете нет |
|-------|-----------------|-------------------|
| `domain` | Карточка, расход, проверка полей, сводка, километр, сравнение периодов | Swing, пути файлов, JSON |
| `storage` | Прочитать и записать журнал, заменить файл через временный, дописать строку сбоя без сумм | Формулы, окна |
| `ui` | Главное окно, форма расхода, блок сравнения, подписи на русском | Запись файла напрямую, своя копия формулы |
| `app` | Собрать объекты и открыть окно | Правил учёта |

Покупных компонентов нет. Повторно используется только JDK: Swing, `java.time`, `java.nio`.

* **More Information:** REQ-MAINT-001, REQ-REUSE-001, ADR-0003. Junior работает в `ui` и читает готовые объекты `domain`.

### VIEW-003. Типы домена

* **Title:** Карточка, расход, период, сводка.
* **Viewpoint:** Логическое представление.
* **Representation:**

| Тип | Поля | Инварианты |
|-----|------|------------|
| `Car` | `name`, `odometerKm` | Имя не пустое после сохранения. Пробег — целое число ≥ 0 |
| `Expense` | `id`, `category`, `date`, `amountKopecks`, `comment`, `odometerKm` | Категория из пяти значений. Дата не позже сегодня. Сумма > 0. Комментарий короче либо равен 200 символам либо отсутствует. Пробег либо отсутствует, либо целое ≥ 0 |
| `Category` | перечисление FUEL, INSURANCE, TAX, REPAIR, OTHER | Набор версии 0.1 не расширяется из интерфейса |
| `Period` | `from`, `to` включительно | `from` ≤ `to`, иначе период не применяется |
| `OwnershipSummary` | итог, сумма каждой категории, цена километра либо признак нехватки данных | Итог равен сумме категорий. Пустой период — итог 0 |
| `PeriodComparison` | две сводки и разность итогов в копейках | Разность = итог второго минус итог первого |

Идентификатор расхода — UUID, его задаёт домен при добавлении. Вторая карточка типа `Car` в приложении не создаётся: `app` держит один экземпляр.

* **More Information:** REQ-FUNC-001 … REQ-FUNC-006, REQ-FUNC-009.

### VIEW-004. Файл журнала

* **Title:** Один JSON в профиле пользователя.
* **Viewpoint:** Информация.
* **Representation:**

Путь: `{user.home}/Avtouchet/ledger.json`.

```json
{
  "car": { "name": "Поло", "odometerKm": 10200 },
  "expenses": [
    {
      "id": "6f1c0e3a-1d2b-4c5d-8e9f-0a1b2c3d4e5f",
      "category": "FUEL",
      "date": "2026-03-05",
      "amount": "125.50",
      "comment": "Трасса",
      "odometerKm": 10000
    }
  ]
}
```

Поле `amount` — строка с двумя знаками. Поле `odometerKm` у расхода опускается, если пользователь его не вводил. Поле `comment` опускается, если комментария нет.

Запись: содержимое собирается целиком, пишется в `ledger.json.tmp`, затем имя заменяется на `ledger.json`. Если проверка полей не прошла, метод записи не вызывается.

Журнал сбоев: `{user.home}/Avtouchet/avtouchet.log`. Строка содержит дату, время и краткую причину сбоя записи. Сумм и комментариев в ней нет.

* **More Information:** REQ-INT-003, REQ-FUNC-007, REQ-SEC-002, REQ-REL-001, REQ-OBS-001, ADR-0002.

### VIEW-005. Вызовы между пакетами

* **Title:** Контракты, которые видит соседний пакет.
* **Viewpoint:** Интерфейс и зависимости.
* **Representation:**

Зависимости направлены так: `ui` → `domain`, `ui` → `storage`, `storage` → `domain`, `app` → все три. Обратных рёбер нет.

Контракты, которых достаточно для реализации:

| Операция | Вход | Выход |
|----------|------|-------|
| `ExpenseDraft.validate` | поля формы | список ошибок по полям либо годный `Expense` |
| `Ledger.filter` | расходы, период | расходы с датой внутри периода, включая границы |
| `Ownership.summarize` | расходы периода | `OwnershipSummary` |
| `Ownership.compare` | две сводки | `PeriodComparison` |
| `LedgerStore.load` | путь | карточка и расходы |
| `LedgerStore.save` | карточка и расходы | файл заменён либо сбой в логе, старый файл на месте |

Сетевого контракта нет. Имена операций — проектные, в SRS их нет намеренно.

* **More Information:** SYS-NF-02, SYS-NF-05, ADR-0003.

### VIEW-006. Сохранение расхода и сравнение

* **Title:** Удачный ввод, отказ ввода, смена второго периода.
* **Viewpoint:** Взаимодействие.
* **Representation:**

Удачное добавление:

1. Пользователь нажимает «Добавить расход». `ui` открывает форму.
2. Пользователь нажимает «Сохранить». `ui` отдаёт поля в `ExpenseDraft.validate`.
3. Домен возвращает `Expense`. Список в памяти пополняется.
4. `ui` вызывает `LedgerStore.save`. Хранилище пишет временный файл и заменяет основной.
5. `ui` заново вызывает `Ownership.summarize` для выбранного периода и для обоих периодов сравнения, затем обновляет подписи.

Отказ ввода:

1. Шаги 1–2 те же.
2. Домен возвращает ошибку поля, например суммы.
3. `ui` показывает сообщение у этого поля. `LedgerStore.save` не вызывается. Сводка на экране остаётся прежней.

Сравнение:

1. Пользователь меняет дату второго периода.
2. Если начало позже конца, `ui` показывает сообщение и не подменяет уже показанные числа.
3. Иначе `ui` фильтрует расходы вторым периодом и вызывает `Ownership.compare`.

Удаление: `ui` спрашивает подтверждение. После отказа список не меняется. После согласия расход убирается из памяти и файл перезаписывается тем же `save`.

* **More Information:** REQ-FUNC-002, REQ-FUNC-004, REQ-FUNC-008, REQ-FUNC-009, REQ-INT-002, REQ-INT-005.

### VIEW-007. Формулы

* **Title:** Километр и разность периодов.
* **Viewpoint:** Алгоритм.
* **Representation:**

Стоимость владения периода — сумма `amountKopecks` расходов, попавших в период. Сумма категории — сумма тех же расходов с этой категорией. Пустой набор даёт 0.

Цена километра:

```text
readings = пробеги расходов периода, где пробег указан
если readings.size < 2 либо max(readings) <= min(readings):
    вернуть «недостаточно данных о пробеге»
иначе:
    копейки_за_км = итог_копеек / (max(readings) - min(readings))
    показать два знака, половина вверх
```

В числителе все категории, не только топливо. Контрольный пример: пробеги 10 000 и 10 200, итог 200.00 BYN → 1.00 BYN за километр.

Сравнение:

```text
разность = сводка_Б.итог - сводка_А.итог
для каждой категории: сводка_Б.категория - сводка_А.категория
цену километра в строке периода показать только если она посчиталась числом
```

Оба алгоритма живут в `domain` и не читают файл сами: файл к этому моменту уже превращён в список расходов.

* **More Information:** REQ-FUNC-005, REQ-FUNC-006, REQ-FUNC-009, REQ-POC-001, ADR-0004.

### VIEW-008. Состояния формы расхода

* **Title:** Черновик не становится записью, пока поля не приняты.
* **Viewpoint:** Динамика состояний.
* **Representation:**

| Состояние | Как попадают | Что можно |
|-----------|--------------|-----------|
| Закрыта | старт, «Отмена», успешное сохранение | Открыть форму |
| Черновик | открыли форму или поправили поле | Править поля, «Отмена», «Сохранить» |
| Показана ошибка | `validate` вернул ошибку | Править поля, «Отмена». Файл не меняется |
| Записана | `validate` прошёл и `save` прошёл | Форма закрывается, список и сводки обновлены |

Из «Показана ошибка» нет перехода в «Записана», пока пользователь не исправит поле и проверка не пройдёт. Сбой самой записи файла оставляет форму открытой, пишет строку в лог и не очищает введённые поля: пользователь может повторить сохранение.

* **More Information:** REQ-FUNC-008, REQ-REL-001, REQ-OBS-001.

### VIEW-009. Запуск и поток

* **Title:** Один процесс, окна на потоке Swing.
* **Viewpoint:** Развёртывание и параллелизм.
* **Representation:**

Узел один: компьютер пользователя с Windows 10 или Windows 11 и Java 17. Процесс один, его запускает команда из собранного артефакта Maven. Рядом с процессом нет службы базы и нет демона.

Окна и обработчики кнопок работают на EDT. Чтение и запись журнала на версии 0.1 тоже выполняются на EDT. Отдельный рабочий поток не заводится: при 5 000 записях запись файла укладывается в ту же секунду, что и пересчёт (SYS-NF-01). Второй поток при таком объёме добавил бы синхронизацию списка расходов без выигрыша, который видит заказчик.

Каталоги `Avtouchet` создаются при первом успешном сохранении, если их ещё нет. В каталог установки программы журнал не кладётся.

* **More Information:** REQ-INST-001, REQ-PORT-001, REQ-PERF-001, ADR-0001, ADR-0002.

## 4. Решения {#4-decisions}

### DEC-001. Стек

* **Title:** Java 17, Swing, Maven.
* **Context:** Нужен desktop без сети и без платного хостинга.
* **Options:** Swing; JavaFX; веб-клиент и сервер.
* **Outcome:** Swing и Maven, потому что UI входит в JDK, а сервер запрещён SRS.
* **More Information:** ADR-0001. Представления VIEW-001, VIEW-009.

### DEC-002. Хранение

* **Title:** JSON и замена файла, не SQLite.
* **Context:** Первая оценка закладывала две недели на встроенную базу. Для одного пользователя и 5 000 строк это не окупалось.
* **Options:** JSON с временным файлом; SQLite; бинарная сериализация Java.
* **Outcome:** JSON, суммы строкой с двумя знаками, в домене — копейки.
* **More Information:** ADR-0002. Представление VIEW-004.

### DEC-003. Границы кода

* **Title:** Пакеты domain, storage, ui, app.
* **Context:** Формулу нужно вызывать из теста до приёмки окон.
* **Options:** три пакета; логика в кнопках; порты на каждый сценарий.
* **Outcome:** три пакета и тонкий `app`. Домен не импортирует Swing.
* **More Information:** ADR-0003. Представления VIEW-002, VIEW-005.

### DEC-004. Сравнение периодов

* **Title:** Числа на главном экране, без графика.
* **Context:** Заказчик вернул сравнение периодов в объём и не сдвинул дату 20.12.2026.
* **Options:** блок на главном экране; отдельное окно с графиком; CSV.
* **Outcome:** блок на главном экране. Расчёт — вычитание двух сводок. График в релиз не входит. Панель отдаётся junior.
* **More Information:** ADR-0004. Представления VIEW-006, VIEW-007. SRS 0.3, требования REQ-FUNC-009 и REQ-INT-005.
