## 1. Введение {#1-introduction}

### 1.1 Назначение документа {#11-document-purpose}

Данный документ описывает архитектуру, дизайн и структуру Desktop-приложения TourReview, разрабатываемого на Java (JavaFX). Документ предназначен для команды разработчиков (для реализации системы), тестировщиков (для понимания внутренней структуры при написании тестов) и сопровождающего персонала. Он базируется на требованиях, зафиксированных в SRS, и служит мостом между требованиями и исходным кодом.

### 1.2 Область применения {#12-subject-scope}

**Система:** TourReview версии 1.0.
**Назначение:** предоставление пользователям возможности создавать отзывы, ставить оценки и прикреплять фото к туристическим местам и объектам аренды, а также предоставление инструментов для модерации контента.
**Входит в область:** Desktop-клиент, локальная база данных SQLite, файловое хранилище для фотографий.
**НЕ входит в область:** серверная часть, облачные хранилища, интеграция с картами, мобильные клиенты.

## 2. Обзор дизайна {#2-design-overview}

### 2.1 Задачи стейкхолдеров {#21-stakeholder-concerns}

* **Турист (пользователь):** нуждается в интуитивно понятном интерфейсе для быстрого поиска мест и оставления отзывов.
* **Арендодатель:** требуется удобный способ добавить новый объект аренды и ответить на отзыв.
* **Модератор:** нуждается в эффективном инструменте для просмотра жалоб, скрытия контента и блокировки недоброжелательных пользователей.
* **Разработчик:** заинтересован в модульной архитектуре, простоте поддержки и сборки через Gradle.
* **Тестировщик:** нуждается в чётком разделении слоёв для написания интеграционных и юнит-тестов.

### 2.2 Выбранные точки зрения {#22-selected-viewpoints}

#### 2.2.1 Контекст {#221-context}
* **Адресует:** границы системы, акторы, внешние системы.
* **Описание:** Система TourReview представляет собой Desktop-приложение. Акторы: Турист, Арендодатель, Модератор, Администратор. Внешние системы отсутствуют (БД является встроенной). Контекстная диаграмма отображена в `use-case.png`.

#### 2.2.2 Композиция {#222-composition}
* **Адресует:** выявление основных элементов дизайна, модульность.
* **Описание:** Система состоит из трёх основных подсистем (слоёв): UI (пакет `ui`), Services (пакет `service`), Repository/DAO (пакет `repository`). Также выделен модуль `PhotoStorage` для работы с файлами.

#### 2.2.3 Логическое представление {#223-logical}
* **Адресует:** статическая структура, классы и их взаимосвязи.
* **Описание:** Основные классы: `User`, `Place`, `Review`, `Reply`, `Complaint`, `AuditLog`. Они связаны отношениями один-ко-многим (например, `Place` -> `Review`). Сервисы (`ReviewService`, `ModerationService`) инкапсулируют бизнес-логику над этими сущностями.

#### 2.2.4 Физическое представление {#224-physical}
* **Адресует:** материальная инфраструктура.
* **Описание:** Не применимо для данного проекта. Приложение работает локально на компьютере пользователя. Физическая топология ограничивается локальным жёстким диском (для файла БД) и оперативной памятью.

#### 2.2.5 Структура {#225-structure}
* **Адресует:** внутренняя организация компонентов.
* **Описание:** PlaceService содержит метод createPlace() для добавления новых мест арендодателем. ReviewService содержит методы createReview(), getAverageRating(). ModerationService содержит getComplaintsQueue(), hideReview() и blockUser(). AuthService проверяет статус isBlocked при входе в систему.

#### 2.2.6 Зависимости {#226-dependency}
* **Адресует:** связанность элементов.
* **Описание:** Слой UI зависит от слоя Service. Слой Service зависит от слоя Repository. Слой Repository зависит от JDBC-драйвера SQLite. Обратные зависимости запрещены (Service не знает о UI).

#### 2.2.7 Информация {#227-information}
* **Адресует:** структура данных и хранение.
* **Описание:** База данных SQLite содержит таблицы:
    * `users` (id, login, role, password_hash, is_blocked)
    * `places` (id, name, avg_rating, review_count)
    * `reviews` (id, place_id, user_id, rating, text, photo_path)
    * `complaints` (id, review_id, reason)
    * `audit_log` (id, moderator_id, action, timestamp)

#### 2.2.8 Интерфейс {#228-interface}
* **Адресует:** взаимодействие между компонентами.
* **Описание:** Взаимодействие между UI и сервисами происходит через вызовы Java-методов. Интерфейсы сервисов описаны контрактами (например, `ReviewService` обязуется вернуть `boolean` при создании отзыва). Взаимодействие с БД осуществляется через стандартный JDBC API.

#### 2.2.9 Взаимодействие {#229-interaction}
* **Адресует:** последовательность сообщений.
* **Описание:** При создании отзыва: UI вызывает `ReviewService.createReview()`. Сервис валидирует данные, сохраняет фото через `PhotoStorage`, вызывает `ReviewRepository.insert()`. Затем `PlaceRepository.updateRating()`. В конце UI получает ответ и обновляет карточку.

#### 2.2.10 Алгоритм {#2210-algorithm}
* **Адресует:** внутренняя логика обработки.
* **Описание:** Алгоритм пересчёта рейтинга: `avg_rating = SUM(rating) / COUNT(reviews)`. Реализуется через SQL-запрос `SELECT AVG(rating) FROM reviews WHERE place_id = ?` и обновление поля `avg_rating` в таблице `places`.

#### 2.2.11 Динамика состояний {#2211-state-dynamics}
* **Адресует:** эволюция состояний.
* **Описание:** Отзыв может находиться в состояниях: `Опубликован` (виден всем), `Скрыт` (виден только модератору), `На рассмотрении` (поступила жалоба). Переход между состояниями инициируется модератором через `ModerationService`. Пользователь также может находиться в состояниях: Активен и Заблокирован. Переход в состояние Заблокирован осуществляется модератором, при этом пользователь теряет возможность оставлять отзывы и подавать жалобы.

#### 2.2.12 Параллелизм {#2212-concurrency}
* **Адресует:** потоки и синхронизация.
* **Описание:** Так как JavaFX требует, чтобы UI обновлялся только из главного потока (JavaFX Application Thread), все длительные операции (запись в БД, сохранение фото) выполняются в фоновых потоках с помощью `Task` и `Platform.runLater()` для обновления UI.

#### 2.2.13 Паттерны {#2213-patterns}
* **Адресует:** проверенные решения.
* **Описание:** Используются паттерны: **MVC** (Model-View-Controller) для разделения интерфейса и логики; **DAO** для инкапсуляции работы с БД; **Singleton** для доступа к `DatabaseConnection`.

#### 2.2.14 Развёртывание {#2214-deployment}
* **Адресует:** отображение на физическое окружение.
* **Описание:** Приложение упаковывается в исполняемый `.jar` (или `.exe` с помощью `jpackage`). Работает локально. Данные хранятся в папке пользователя (`%APPDATA%/TourReview/` или `~/.tourreview/`).

#### 2.2.15 Ресурсы {#2215-resources}
* **Адресует:** использование ограниченных ресурсов.
* **Описание:** Основные ресурсы — это файлы фотографий (потребление дискового пространства) и соединения с БД. Для предотвращения утечек соединений используется паттерн `try-with-resources` (JDBC). Фото ограничены размером 5 МБ.

## 4. Решения {#4-decisions}

* **ID:** 001-Embedded-DB
* **Title:** Использование встроенной SQLite для хранения данных
* **Context:** Приложение Desktop, развёртывание сервера БД нецелесообразно.
* **Options:** PostgreSQL, H2, SQLite.
* **Outcome:** Выбрана SQLite (не требует сервера, хранит данные в одном файле).
* **More Information:** Детали в `adr/adr-001-architecture-decisions.md`.

* **ID:** 002-JavaFX
* **Title:** Использование JavaFX для UI
* **Context:** Необходим современный интерфейс с разделением логики.
* **Options:** Swing, JavaFX.
* **Outcome:** Выбран JavaFX (FXML, CSS).
* **More Information:** Детали в `adr/adr-001-architecture-decisions.md`.
