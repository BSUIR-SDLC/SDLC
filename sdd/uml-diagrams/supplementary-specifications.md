# Дополнительные спецификации

Дополнительные спецификации — общие правила и ограничения, действующие сразу в нескольких сценариях. Например, резерв на 20 минут и проверка владельца заказа относятся и к покупке, и к оплате, и к просмотру статуса. Эта спецификация уточняет чтение UML-модели и не изменяет SRS 0.3. Требования и критерии приёмки остаются в SRS.

| Правило | Ограничение модели | Источник |
|---|---|---|
| Границы релиза | BYN, тестовая онлайн-оплата; без возврата, перепродажи, рассылок и офлайн-входа | SRS 1.2 |
| Покупка | 1–5 различных мест одного типа; атомарно все либо ни одного; цена серверная и фиксируется | FUNC-006–007 |
| Резерв | E=min(expires_at,sales_close); expires_at=min(t+1200 s,sales_close); действие только при t<E | FUNC-007–008, 023 |
| Сессия | 900 s бездействия; выход/вход не освобождает и не продлевает заказ | SEC-005; ADR 0003 |
| Предупреждение | Пересечение с оплаченными покупками не запрещает покупку при явном подтверждении актуального списка | FUNC-024 |
| Оплата | Подпись/подлинность, сумма, валюта, заказ и платёжная сессия проверяются до изменения данных | INT-003, FUNC-010 |
| Позднее событие | Новый подлинный успех при t≥E не выдаёт билеты; PAID от повторов не меняется | FUNC-010–011 |
| Уведомление | Дедупликация event_id и бизнес-эффект фиксируются в одной транзакции; HTTP банка вне блокировок инвентаря | REL-001–002; ADR 0004 |
| Освобождение | Истёкшие/отклонённые резервы освобождаются не позднее 15 s от границы | FUNC-008, 010 |
| Допуск | PAID, VALID, назначенный контролёр, [start−3600 s,end); один USED + Admission | FUNC-014–016 |
| Конкурентность | Один успех из 10 одновременных проверок; остальные возвращают первый допуск | FUNC-015 |
| Публикация | Непересекающиеся полуоткрытые интервалы организатора и площадки | FUNC-022 |
| CSV | UTF-8 BOM, «;», 1–5 строк типов, исторические цены; без персональных полей; один snapshot_at | FUNC-025; ADR 0006 |
| Безопасность | Проверять сессию, роль, владельца/назначение на сервере; не доверять URL возврата оплаты | SEC-001–005 |

Коды AWAITING_PAYMENT, PAID, DECLINED, EXPIRED, REQUIRES_REVIEW соответствуют состояниям Order в SDD 011. Проверка времени производится после получения блокировок. Равенство t=E означает истечение; ранний снимок клиентского времени не даёт права на продажу. Завершённые заказы не удаляются, поэтому конечный узел автомата не используется.

Диаграмма деятельности показывает основной поток покупки; её альтернативы заданы UC04–UC07 и автоматом Order в SDD 011. Диаграмма последовательности показывает координацию модулей при оплате; условия альтернатив определены в UC07 и автомате Order в SDD 011. Сценарий допуска описан в UC09. Отказы не обозначают успешный допуск.
